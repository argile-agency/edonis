<objective>
This plan covers the first two steps of the DEBT-08 sequence: **widen, then scan/repair**. The third step (decryption failures become loud) is plan 02-07. 02-07 ships its raise behind `PII_DECRYPT_STRICT`, which defaults to off and is switched on per environment only after this plan's scan is clean there.

There is a live bug today. `users.phone` and `users.mobile_phone` are `varchar(20)`, but the ciphertext for a phone number is about 110 characters. On PostgreSQL and on strict MariaDB/MySQL (production), saving a profile with a phone number fails behind a generic flash. On non-strict MySQL the value is silently truncated and lost. This plan widens both columns and adds a read-only-by-default scan command. The command finds legacy-plaintext and undecryptable cells before decryption starts raising, and audits every repair it makes.

Purpose: DEBT-08 prerequisites ("PII columns can hold ciphertext; existing rows scanned/repaired before raising is enabled").

Output: the widen migration with a guarded `down()`, `PiiScanService` + `node ace pii:scan` (audited mutations), and `tests/functional/pii.spec.ts`.
</objective>

`@adonisjs/encryption@6.0.2`: `encryption.decrypt(value)` **never throws**. It returns `null` for:
- non-string input
- the wrong number of dot-separated parts
- bad base64
- HMAC mismatch (wrong/rotated APP_KEY, truncated ciphertext)
- decipher errors

Measured ciphertext lengths: `"0612345678"` is 110 characters; a 30-character address is 131 characters.

`EncryptionService` (`app/services/encryption_service.ts`, NOT modified by this plan): `encrypt(value)` returns `encryption.encrypt(value)` for non-empty values. `decrypt` currently returns `encryption.decrypt(v) ?? v`, so it silently falls back to the raw value. Plan 02-07 changes that.

CSRF in this plan's spec (wave 1). Shield enforces CSRF on POST/PUT/PATCH/DELETE in the functional suite (`config/shield.ts`). This spec therefore defines a **spec-local helper** that does exactly what Shield's plugin does (verified in `node_modules/@adonisjs/shield/build/src/plugins/api_client.js`):
- `import Tokens from 'csrf'`. The package is `csrf@3.1.0`, hoisted at `node_modules/csrf` as a dependency of `@adonisjs/shield`, with its own `index.d.ts`, so no install is needed.
- `function withCsrf<T extends ApiRequest>(request: T): T` creates `new Tokens()`, `secret = tokens.secretSync()`, and returns `request.withSession({ 'csrf-secret': secret }).header('x-csrf-token', tokens.create(secret))`.
- `withSession` merges with `loginAs`'s session data, so the order of `.loginAs(...)` and `withCsrf(...)` does not matter.
- The helper is temporary. Plan 02-07 (wave 2, depends on 02-01 and 02-02) takes ownership of `pii.spec.ts`. It converts every `withCsrf(...)` call to `.withCsrfToken()` and deletes the helper and the `csrf` import, as 02-08 does for `two_factor.spec.ts`.
