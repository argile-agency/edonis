# Phase 2 Plan 01: Bouncer policy layer, CSRF-capable test harness and Inertia 403 page

This plan installs Bouncer 3.1.6 and adds `CoursePolicy` and `EnrollmentPolicy`, which keep today's access rules unchanged (admins are still denied the gradebook). Functional specs can now send CSRF tokens through `shieldApiClient()`, and Bouncer denials render an Inertia `errors/forbidden` page with status 403. The gradebook now goes through `CoursePolicy` from end to end.

## Forbidden-page axe case

The test `forbidden page has no critical a11y violations` has been added to `tests/browser/accessibility.spec.ts`. It picks its course with Lucid: a course the seeded student neither owns nor is enrolled in. With the current seeders that is 6 courses minus the 3 the student is enrolled in. If no such course exists, it fails with `assert.fail` and a message naming the seeders. It never skips. Besides `403`, it asserts the page heading `Accès refusé`. That rules out the Edge `server_error` fallback, which would also show `403` if the Inertia render failed.

**I could not run it locally.** Port 3333 is held by the user's running dev server (`bin/server.js`, PID 7773). The browser client's `baseURL` is hard-coded to `http://localhost:3333` in `tests/bootstrap.ts`, which this plan must not change further. The run would therefore have hit the dev server and its database, not the test server. Playwright chromium is installed. The e2e run in CI (`.github/workflows/e2e.yml`, seeded, port 3333) is the authoritative proof on the PR.

   - **Commit:** a457959

   - **Issue:** The precondition read `(await User.findOrFail(...)).termsAcceptedAt`.
   - **Fix:** Split into a local `before` variable. I also check the fresh row instead of the in-memory model, whose `termsAcceptedAt` is `undefined` after `create`, not `null`.

   - **Issue:** The generated `app/abilities/main.ts` shipped an example `editUser` ability that always returns `true`. The plan says both "accept as generated" and "with no abilities defined".

   - **Commit:** d83184f
5. **CSRF grep gate kept meaningful**
   - **Issue:** Prettier splits `await client.post(...).withCsrfToken().loginAs(...).redirects(0)` across lines, which would leave `client.post(` with no match for the grep gate.

6. **`'403'` literal in a comment**
   - **Issue:** The acceptance grep `grep -c "'403'" handler.ts` must be 0, and my comment contained `'403'`.

   - **Issue:** The plan wants `Promise<void>` on the signature line. Prettier wraps the signature over several lines, so `Promise<void>` is on the closing `): Promise<void> {` line, not the `export async function` line.
