Policy key: `'CoursePolicy'`. Actions:

| action | signature |
|---|---|
| `view` | `(user, course)` |
| `edit` | `(user, course)` |
| `manage` | `(user, course)` |
| `delete` | `(user, course)` |
| `administer` | `(user)`, no resource |
| `learn` | `(user, course)` |
| `viewGradebook` | `(user, course)` |
| `viewGradebookAsInstructor` | `(user, course)` |
| `enroll` | `(user, course)` |

`before()` grants admins every action except the two gradebook ones.

Named export from the same file: `export async function scopeVisibleCourses(query: ModelQueryBuilderContract<typeof Course>, user: User): Promise<void>`.
- It applies today's role-based listing filter by **mutating `query` in place**, and returns nothing.
- For managers and teachers it adds one grouped `where((b) => b.where('instructor_id', ...).orWhereHas('permissions', ...))`, so filters chained afterwards apply to the whole OR.
- Call shape: `const query = Course.query().preload('instructor')`, then `await scopeVisibleCourses(query, user)`, then keep chaining on `query`.
- **Never** write `let query = scopeVisibleCourses(...)` or `query = await scopeVisibleCourses(...)`. The function resolves to `undefined`, and a returned Lucid builder would be a thenable that resolves to rows.

Controller usage:
- `async action({ bouncer, ... }: HttpContext)`
- `await bouncer.with('CoursePolicy').authorize('edit', course)` throws → `errors/forbidden` (403) via the handler
- `await bouncer.with('CoursePolicy').allows('edit', course)` → boolean

Test helpers (`tests/functional/helpers/factories.ts`): `uniqueSuffix`, `ensureRole`, `createUser({ roles })`, `createCourse(instructor, overrides)`, `grantPermission(course, user, level)`, `enrollUser(course, user)`, `createEnrollmentMethod(course, overrides)`, `createGroup(course, overrides)`, `assertNotCsrfRejected(assert, response)`.

CSRF (02-01): `shieldApiClient()` is registered in `tests/bootstrap.ts`, so `.withCsrfToken()` exists on every request. Shield enforces CSRF on POST/PUT/PATCH/DELETE before any route middleware. An un-tokened write gets a 302 back with flash `errorsBag.E_BAD_CSRF_TOKEN`, never a 403 or 404.

Route gates that stay as they are (`start/routes.ts`; this plan does not edit it):
- `courses.edit/update/destroy/publish/archive/permissions.*`: `role: admin|manager|teacher`
- `/admin/courses/*` and `/admin/courses/approval-queue|:id/approve|:id/reject`: `role: admin`
- `role_middleware` returns a JSON 403 before the controller runs, so use a teacher (not a student) to exercise POLICY denials on those routes.
