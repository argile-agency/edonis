<objective>
This plan is the third and final step of the DEBT-08 sequence (widen → scan/repair → **raise**): decryption failures become loud.

Today `EncryptionService.decrypt` returns `encryption.decrypt(v) ?? v`. `decrypt` never throws; it returns `null`. So a corrupt or plaintext cell is silently handed to the app, to Inertia props, to the GDPR export and to the audit logs. 2FA secret decryption failures, for example after an `APP_KEY` rotation, lock users out with "Code invalide" and leave no log.

Raising inside a Lucid `consume` hook runs on every `User` hydration, including `auth.check()` on every request. So:
- the plan **starts with a blocking production check** (locked user decision Q1)
- the raise sits behind a new env flag, `PII_DECRYPT_STRICT`, which **defaults to off**. With the flag off, a failure is still logged and is never returned raw: the field reads as `null`. Merging or deploying this plan can therefore never start raising; an operator turns raising on per environment only after that environment's `pii:scan` is clean.

Purpose: DEBT-08, success criterion 5 ("decryption failures are logged and never returned raw in all modes; raises when PII_DECRYPT_STRICT=true"). Strict mode is the raise. The default mode keeps the "logged, never raw" half, and makes the raise an explicit, reversible operator step.

Output:
- the Q1 checkpoint
- `DecryptionException`
- `EncryptionService.decrypt`, gated by `PII_DECRYPT_STRICT`, documented in `.env.example`
- `User` consume hooks that pass the column and id
- silent-auth rethrow
- instrumented `TwoFactorService`
- unit and functional specs covering both modes
</objective>
