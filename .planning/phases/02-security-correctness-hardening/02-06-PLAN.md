<objective>
Fix the category hierarchy where its bug actually lives: on the **write path**. Research proved that `buildTree` cannot loop, because it starts from roots and a cycle is unreachable from a root. However, `CategoriesController.update` accepts a parent that is the category itself or one of its descendants. When that happens, the whole subtree silently vanishes from the admin tree while it still holds courses. Moving or renaming a category also refreshes `path` for direct children only, leaves grandchildren stale, and never updates children's `depth`.

The only true infinite loop is `CourseCategory.getFullPath()`. It has no callers today, and it gets bounded here.

Purpose: DEBT-07, reworded success criterion 4. The plan also covers DEBT-05 inventory item V8 (`categories.reorder` reads raw `request.only`) and moves this controller's inline validators into `app/validators/category.ts`.

Output:
- a pure helper (also reused by plan 02-10 for module parents)
- its unit spec
- the bounded `getFullPath`
- validated, cycle-safe, transactional `update` and validated `reorder`
- a read-only integrity command
- a functional spec
</objective>
