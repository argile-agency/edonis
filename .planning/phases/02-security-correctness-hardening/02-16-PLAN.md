<objective>
Close verification gap CR-03: `CoursesController.show` preloads every module, child module and content row (no `is_published` filter) and sends `modules.map((m) => m.serialize())` to every viewer who passes `CoursePolicy.view`, which is true for any public course whatever its status. Content serialization includes page `content` bodies, `fileUrl` and `externalUrl`. This bypasses the user-approved AS3 restriction.

Purpose: DEBT-04 ("authorization applied uniformly"); verification truth 7.
Output: tree only for edit-rights holders (Task 1, no visible change), `view` narrowed to published public courses for non-staff, non-enrolled users (Task 2, behaviour change, own commit), user checkpoint (Task 3), regression spec.

Design decisions (planner, justified):
- Tree recipients = `canEdit` only (owner, `edit`/`manage` co-instructors, admins). This deviates on purpose from the orchestrator wording "staff/enrolled users still get them as before". `inertia/pages/courses/show.tsx` reads `modules` only inside the `permissions.canEdit` content tab (lines 541-577; prop defaults to `[]`), so enrolled students and view-only collaborators never saw the tree on screen. Removing it from their props changes nothing visible, and it also stops shipping unpublished bodies to enrolled students (they read material through the AS3-gated outline/learn routes). This is the smaller and safer of the two options; a titles-only public outline would be new code that no page renders.
- The tree is loaded after authorization with `course.load('modules', ...)` only when `canEdit`, so bodies are not even read from the database for other viewers.
- `view` narrowing (verifier "require course.isPublished() for non-staff viewers") is a user-visible behaviour change, so it ships alone behind a checkpoint, with its test updates in the same commit (as 02-10 did for AS3) so a revert leaves a green suite. It keeps an enrolled exception so students of archived public courses keep the course page. It does NOT widen private/unlisted access.
- Depends on 02-15 because both plans modify `app/policies/course_policy.ts` and `app/controllers/courses_controller.ts`.
</objective>
