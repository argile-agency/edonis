<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /edit-mode` | untrusted JSON body (enabled, courseId, from) |
| session store → shared Inertia props | flag written by one account, read on every request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.3-01 | Tampering | `POST /edit-mode` cross-site request | mitigate | shield CSRF + XSRF cookie (no exception added); spec asserts a token-less POST is rejected and every success uses `assertNotCsrfRejected` |
| T-05.3-02 | Spoofing (open redirect) | `from` field | mitigate | `vine.enum(['show','learn','builder'])` + fixed `BACK_TO` map of named routes; no `back()`, no client URL; spec sends `from: 'evil'` |
| T-05.3-03 | Elevation of privilege | toggle used on a course the user cannot edit | mitigate | role middleware (admin/manager/teacher) + `CoursePolicy.edit` via `denies()`; the builder still runs `authorize('edit')`, so the flag grants no right |
| T-05.3-04 | Information disclosure / elevation (UI) | flag leaking to the next account on a shared browser | mitigate | flag stores `userId`, `isEditModeOn` compares it with `auth.user.id`; `session.forget` in logout; spec covers another userId and logout |
| T-05.3-05 | Tampering | malformed body | mitigate | VineJS validator (boolean, positive integer, enum); `Course.findOrFail` → 404 |
| T-05.3-06 | Repudiation | toggle not audited | accept | per-session view preference, grants no right; not in CLAUDE.md's security-relevant list |
| T-05.3-07 | Elevation (UI only) | student-role user with an `edit` course permission sees the switch | accept | toggle answers 403 from the role middleware, same as today's builder link (Pitfall 8) |
</threat_model>
