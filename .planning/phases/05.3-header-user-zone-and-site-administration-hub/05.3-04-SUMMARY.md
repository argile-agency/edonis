# Phase 05.3 Plan 04: Header rebuild on the Moodle model Summary

The shared header is rebuilt as one h-16 row. It holds the brand, the nav with the filled « Tableau de bord » button, and the user zone in this order: wrench, search, theme, bell, messages, avatar with caret, then « Mode d'édition ». The bell and messages buttons are aria-disabled placeholders with tooltips. Below `lg`, a ☰ disclosure panel holds search, nav, « Tableau de bord », the admin link and the edit-mode switch. For visitors, the panel holds the nav and « Inscription ». The `AppHeader({ user, appSettings, menus })` signature is unchanged.

## What was built

- `<TooltipProvider delayDuration={300}>` wraps the row and the panel, as the 05.3-02 handoff required. SSR renders without throwing for both a visitor and an admin.
- The brand is a `Link` that contains a span, not an `<h1>`. The `GraduationCap` fallback is `aria-hidden`.
- The admin wrench is `hidden lg:inline-flex` and links to `/admin`. In the avatar menu, « Administration du site » → `/admin` replaces « Réglages de la plateforme » / `SlidersHorizontal`.
- The bell and messages buttons are `PlaceholderButton`s named « Notifications (bientôt disponible) » and « Messages (bientôt disponible) », with the tooltip « Bientôt disponible ».
- The avatar trigger is named « Menu du compte » and has a `ChevronDown` caret. The identity name is `font-bold`. « Messages personnels (bientôt disponible) » stays disabled.
- The edit-mode block (Separator plus `EditModeSwitch id="edit-mode-switch"`) renders at ≥ lg when `courseEditing.canEdit`. The panel copy uses `id="edit-mode-switch-mobile"`.
- The ☰ button has `aria-expanded` and `aria-controls="mobile-menu"`, with the label « Ouvrir le menu » / « Fermer le menu ».
  - The panel uses `hidden={!menuOpen}`.
  - `router.on('navigate')` closes both the panel and the search.
  - Escape closes the panel and refocuses ☰.
  - Nothing reads `window` or `matchMedia` during render.
- Visitors below lg see brand, theme, « Connexion » and ☰. The bar's « Inscription » is `hidden lg:inline-flex`, and a full-width copy sits in the panel.
- `theme-toggle.tsx` adds `rounded-full` to its trigger.

## Open question 14 and row wrapping

- **Caret rotation: generated.** The built CSS contains `group-data-\[state\=open\]\:rotate-180:is(:where(.group)[data-state=open] *){rotate:180deg}`. `sm:not-sr-only`, `lg:sr-only`, `xl:not-sr-only` and `hover:bg-[hsl(var(--muted))]` were also generated.
- **Wrapping: not visually inspected at any width.** This is deferred to the browser tests in 05.3-05 and the walkthrough in 05.3-06. The row is `flex` without `flex-wrap`, so it cannot wrap. Under width pressure the nav (`overflow-hidden`) clips instead, and it is hidden while the bar search is open between lg and xl.

## Deviations from Plan

1. **[Rule 1 - Bug] Escape double-handling with open Radix menus** (commit 9778a67). Radix DismissableLayer handles Escape in the capture phase and calls `preventDefault()`. Without a guard, the document listener would also close the panel and steal focus from the dropdown trigger. The handler now returns early when `e.defaultPrevented` is set: the first Escape closes the menu, the second closes the panel.
2. **Brand name accessibility.** Instead of `hidden xl:inline` plus a second sr-only span, a single span toggles `sr-only sm:not-sr-only lg:sr-only xl:not-sr-only` for signed-in users. It gives the same visual result and keeps the link's accessible name at every width with one element. When a logo `<img alt>` is present, the name is announced twice, as it was before.
3. **Worktree base.** The worktree started at b9888ef. As the branch-check instruction requires, it was reset to 5a68fc6 (the wave-1 base) before any work.
4. **SSR verification method.** A temporary script (deleted afterwards) rendered `home` (visitor) and `dashboard` (admin) through `build/ssr/ssr.js`. No functional tests were run, so better-sqlite3 was not rebuilt. The edit-mode branch was not exercised under SSR, because `dashboard` is not in the switch's component map.
