# Phase 5.3: Header user zone and site administration hub - Context

**Gathered:** 2026-11-10
**Status:** Ready for planning

<domain>
## Phase Boundary

The right-hand "user zone" of the shared header is rebuilt on the Moodle model so users moving from Moodle keep their habits: admin shortcut, course search, theme toggle, notification and message entry points, avatar menu with a caret, and a « Mode d'édition » switch inside courses. Admins get one site administration page that links every existing admin page. Messaging, notifications and global search are NOT built here (placeholders only). The reference is the CyberLearn Moodle header and its « Administration du site » page (owner screenshots, 2026-11-10); the third-party portfolio icon is excluded.

</domain>

<decisions>
## Implementation Decisions

### Scope decisions (owner, 2026-11-10, at phase insertion)
- **D-01:** Notification bell and message button are **placeholders**: visible to signed-in users, disabled, tooltip « Bientôt disponible », accessible name says so. No notification or message table, route or model in this phase.
- **D-02:** Search covers **courses the user can see** (title, description, code), nothing else.
- **D-03:** « Mode d'édition » switches between the course's normal view and the **existing builder** (`/courses/:id/builder`); no in-place editing on the learner view.
- **D-04:** Phase sits in the v0.1 MVP between 5.2 and 6.
- **D-05:** The portfolio icon from the reference screenshot is excluded.

### Header layout
- **D-06:** **One row** on desktop (owner rejected the Moodle two-row layout): logo + app name left, navigation links, then the user zone on the right. Planner must make it hold at `md`–`lg` widths (see D-15 for the search, and collapse rules are Claude's discretion).
- **D-07:** User zone order, left to right: **admin icon** (wrench/screwdriver, admins only) → **search** → **theme toggle** → **bell** → **messages** → **avatar + caret** → **« Mode d'édition »** (only when D-11 applies). The theme toggle moves out of the logo block into the user zone and stays available to signed-out visitors.
- **D-08:** The **« Tableau de bord » button stays a filled button** (owner choice, not turned into a plain link).
- **D-09:** **Mobile: hamburger menu** (☰) opening a panel with the navigation links and the search; logo, bell, messages and avatar stay visible in the bar; the admin icon and the edit-mode switch move into the panel. Fixes today's gap (navigation is `hidden md:flex` with no mobile replacement).
- **D-10:** The avatar trigger shows a **caret (chevron-down)** next to the avatar; trigger keeps an accessible name (e.g. « Menu du compte »).

### Edit mode
- **D-11:** The switch appears on **every course page** — course page `/courses/:id`, learner view `/courses/:id/learn`, builder `/courses/:id/builder` — **only for users allowed to edit that course** (`CoursePolicy.edit`). Hidden everywhere else (home, dashboard, admin) and never shown to students.
- **D-12:** Turning it **on** opens the builder; turning it **off** in the builder returns to the learner view.
- **D-13:** The mode **persists across courses** like Moodle: while it is on, opening another course the user can edit lands directly in the builder, until they turn it off.
- **D-14:** Stored **in the session** (reset on logout). No migration, no user column, nothing to add to the GDPR export.

### Claude's Discretion
- **D-15 Search UX:** a magnifier icon that expands into a text field on click (keeps the single row tight); Enter submits to the existing course list `/courses?search=` (`CoursesController.index` already filters title/description/code). No live suggestions in this phase. Signed-in users only (the `/courses` route requires auth); hidden for visitors.
- **D-16 Site administration page:** new route `/admin` (admin only, route middleware + policy check, same as 5.1 D-12), shared layout with header. Tabs with `inertia/components/ui/tabs.tsx`, French labels, each tab a list of links grouped by heading, Moodle style. Starting map (planner may adjust):
  - **Général** — Réglages de la plateforme (`/admin/settings`, its 4 tabs as sub-links if useful), Journal d'audit (`/admin/audit-logs`)
  - **Utilisateurs** — Liste des utilisateurs (`/admin/users`), Créer un utilisateur
  - **Cours** — Tous les cours (`/admin/courses`), File d'approbation, Catégories (`/admin/categories`), Créer un cours
  - Notes, Plugins, Rapports and the other Moodle tabs are **not** created empty; a tab exists only when it has at least one real link.
  - No search box inside the admin page in this phase.
- **D-17 Admin entry points:** the wrench icon and a « Administration du site » item in the avatar menu both go to `/admin`. The existing « Réglages de la plateforme » menu item (5.1 D-02) is kept or folded into it, planner's call. Managers and teachers see neither (admin pages are admin-only today).
- **D-18 Avatar menu content:** keep the current groups (profile, grades, disabled future items, settings, account, language, logout); add the admin item for admins. The disabled « Messages personnels » item stays consistent with the placeholder message button.
- Overflow behaviour between `md` and `lg` (e.g. which items fold into the hamburger first).

</decisions>

## Existing Code Insights

### Reusable Assets
- `inertia/components/layout/app-header.tsx` (290 lines): the header to rebuild; already has the avatar `DropdownMenu` with groups and disabled future items, admin-only « Réglages de la plateforme » item, `ThemeToggle`, logout.
- `inertia/components/layout/app-layout.tsx`: shared layout (header + footer) used by every page since commits 916cb57..ace67d6.
- `inertia/components/ui/`: `dropdown-menu`, `tabs`, `switch` (edit-mode toggle), `input`, `button`, `avatar`; lucide icons (`Wrench`, `Search`, `Bell`, `MessageSquare`, `ChevronDown`, `Menu`).
- `app/policies/course_policy.ts` → `edit(user, course)`: the gate for showing the edit-mode switch.
- `CoursesController.index` (`app/controllers/courses_controller.ts:72-93`): existing `search` filter on title/description/code.

### Established Patterns
- Admin routes: `middleware.auth()` + `middleware.role({ roles: ['admin'] })` plus a policy check in the controller (`platform_settings_policy.ts`).
- Shared Inertia props feed the header (`user`, `appSettings`, `menus`); the edit-mode state and "can edit this course" flag need to reach the header the same way (shared prop or page prop).
- Browser a11y tests in `tests/browser/accessibility.spec.ts`.

### Integration Points
- Course routes: `/courses/:id` (`CoursesController.show`), `/courses/:id/learn` and `/courses/:id/builder` (`CourseContentsController`) — D-13 redirect hook when edit mode is on.
- `start/routes.ts`: new `/admin` hub route and a small endpoint (or form post) to toggle the session flag.
- `database/seeders/menu_seeder.ts`: user-menu admin item from 5.1.

</code_context>

<specifics>
## Specific Ideas

- "Récupérer les habitudes qu'ont les utilisateurs venant de Moodle dans la tentative de conversion": the edit-mode switch and the admin wrench are the key Moodle cues; keep the label « Mode d'édition » verbatim.
- Admin page look: section heading on the left, list of links on the right, horizontal separators between sections (Moodle screenshot).

</specifics>

<deferred>
## Deferred Ideas

- **Notifications** (bell with unread count, event sources such as enrolment, course approval, submissions): own phase.
- **Private messaging** between users: own phase.
- **Live search suggestions / global search** (contents, users, settings) and **search inside the admin page**.
- Admin tabs with no content yet (Notes, Plugins, Rapports, Serveur…): appear when their pages exist.
- Manager access to a subset of the administration page.

</deferred>
