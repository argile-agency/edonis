## Summary

Almost everything this phase needs already exists. Edit mode needs four pieces:
- a shared Inertia prop next to `auth` in `config/inertia.ts`;
- a page prop (`courseEditing`) added to three `inertia.render` calls;
- one small POST endpoint with a VineJS validator;
- an early redirect in `CoursesController.show`.

The header reads the props through `usePage()`, which `flash-toaster.tsx` and `terms-consent-banner.tsx` already do, so `AppLayout` and the pages do not change. The admin hub is a route plus a one-line controller that reuses `PlatformSettingsPolicy.manage`, and a static Inertia page. `GET /admin` is not routed today, so it does not collide with the `/admin` prefix groups. The only new dependency is `@radix-ui/react-tooltip`. It shares its sub-dependencies (popper, portal, dismissable-layer) with the installed dropdown-menu.

Four findings from source contradict the approved UI-SPEC and must reach the planner:
1. **Logout does not reset the session flag.** The session guard's `logout()` only forgets the auth key, and `login()` → `regenerate()` keeps session data. D-14 therefore needs an explicit `session.forget` and a user-id check.
2. **On an Inertia POST, `bouncer.authorize()` renders the full 403 page**, not a flash. To get the UI-SPEC's "flash error, switch unchanged" state, use `denies()` + flash + redirect.
3. **An unconditional D-13 redirect in `show` makes the course page unreachable for editors while the mode is on.** That includes every course for admins, because `CoursePolicy.before` returns true. « Retour au cours » links (builder.tsx:862, learn.tsx:280/435) bounce back into the builder.
4. **`updateOrCreate` on the `/admin/settings` seed key would duplicate the `/admin` user-menu row that already exists.**

**Primary recommendation:**
- Key the session flag as `{ userId, courseId }`.
- Redirect in `show` only when the course differs from the last course opened in edit mode (Open Question 1, an owner call).
- Hand-write `ui/tooltip.tsx` from the shadcn new-york source and `bun add @radix-ui/react-tooltip`. Do not run `bunx shadcn add`.

### Pattern 1: Shared prop from session, keyed to the user
```ts
// app/helpers/edit_mode.ts
import type { HttpContext } from '@adonisjs/core/http'
export const EDIT_MODE_KEY = 'editMode'
export type EditModeState = { userId: number; courseId: number }

/** On only for the user who turned it on (session data survives login/regenerate). */
export function readEditMode(ctx: HttpContext): EditModeState | null {
  const state = ctx.session.get(EDIT_MODE_KEY) as EditModeState | undefined
  return state && ctx.auth?.user && state.userId === ctx.auth.user.id ? state : null
}

// config/inertia.ts — sharedData, next to `auth`
editMode: (ctx) =>
  ctx.inertia.always(() => {
    try {
      return readEditMode(ctx) !== null
    } catch {
      return false
    }
  }),
```
Source: the `sharedData` structure and try/catch pattern in `config/inertia.ts` [VERIFIED: codebase]. `InferSharedProps` picks up the new key automatically, so the client type follows.

### Pattern 2: Endpoint (validator + policy re-check + whitelisted redirect)
```ts
// app/validators/edit_mode.ts
export const editModeValidator = vine.compile(
  vine.object({
    enabled: vine.boolean(),
    courseId: vine.number().positive().withoutDecimals(),
    from: vine.enum(['show', 'learn', 'builder'] as const),
  })
)

// app/controllers/edit_mode_controller.ts
const ROUTE = { show: 'courses.show', learn: 'courses.learn', builder: 'courses.learn' } as const

export default class EditModeController {
  async update(ctx: HttpContext) {
    const { request, response, session, bouncer, auth } = ctx
    const { enabled, courseId, from } = await request.validateUsing(editModeValidator)
    const course = await Course.findOrFail(courseId)
    // denies(), not authorize(): authorize renders the full 403 page on Inertia requests
    if (await bouncer.with('CoursePolicy').denies('edit', course)) {
      session.flash('error', 'Vous ne pouvez pas modifier ce cours. Contactez son responsable.')
      return response.redirect().toRoute('courses.show', { id: course.id })
    }
    if (enabled) {
      session.put(EDIT_MODE_KEY, { userId: auth.user!.id, courseId: course.id })
      return response.redirect().toRoute('courses.builder', { id: course.id })
    }
    session.forget(EDIT_MODE_KEY)
    return response.redirect().toRoute(ROUTE[from], { id: course.id })
  }
}

// start/routes.ts — mirrors the builder group's gates
router
  .post('/edit-mode', [EditModeController, 'update'])
  .as('edit-mode.update')
  .use(middleware.auth())
  .use(middleware.role({ roles: ['admin', 'manager', 'teacher'] }))
```
- **CSRF:** `config/shield.ts` has `csrf.enabled` and `enableXsrfCookie: true`, so Inertia's `router.post` sends `X-XSRF-TOKEN` automatically. No exception is needed. Tests use `.withCsrfToken()`.
- **Audit log: not needed.** The flag is a per-session view preference. It grants no right, because the builder re-authorizes `edit`. It is not in CLAUDE.md's "security-relevant actions".
- **Rate limit: not needed.** This is not an auth endpoint, and it only writes the session.

### Pattern 4: Header component (SSR-safe)
- One `<TooltipProvider delayDuration={300}>` wraps the header content.
- **State:** `searchOpen` and `menuOpen` both start `false`, so the server render and the first client render match.
- **Closing on navigation:** close both in `useEffect(() => router.on('navigate', () => {…}), [])`. `router.on` returns its unsubscribe function, so the effect cleans up after itself.
- **Search focus:** do not use `autoFocus`. `jsx-a11y/recommended` is on for `inertia/**/*.tsx` (`eslint.config.js:14-17`), and `jsx-a11y/no-autofocus` is `error`. Focus the input from an effect through a ref when `searchOpen` turns true. Return focus to the magnifier button on Escape.
- **Placeholders:** `<TooltipTrigger asChild><Button variant="ghost" size="icon" aria-disabled="true" aria-label="Notifications (bientôt disponible)" onClick={(e) => e.preventDefault()} className="h-9 w-9 rounded-full opacity-50 cursor-not-allowed hover:bg-transparent">`. Never use `disabled`: `button.tsx` adds `disabled:pointer-events-none`, so hover and focus would never reach the tooltip.
- **Wrench:** `TooltipTrigger asChild` > `Button asChild` > `Link href="/admin"`. Nested Slots compose.
- **Edit-mode switch:**
  - Render when `courseEditing?.canEdit === true`. Pass `checked={editMode}`.
  - `onCheckedChange={(next) => router.post('/edit-mode', { enabled: next, courseId, from }, { onStart, onFinish })}` with a local `processing` state.
  - Derive `from` from `usePage().component` (`'courses/show' | 'courses/learn' | 'courses/builder'`). That avoids threading any prop.
- **Admin detection** stays `user.roles.some((r) => r.slug === 'admin')`, as today. `check:debt` only greps `app/controllers`, so it does not flag frontend code.

### Pattern 5: Admin hub
```ts
// app/controllers/admin_hub_controller.ts
```

- **Link targets exist** for all of the following:
  - `/admin/settings?tab=` with `appearance|home|access|contact|trash` (`SETTINGS_TABS`);
  - `/admin/audit-logs`, `/admin/users`, `/admin/users/create`;

### Anti-Patterns to Avoid
- **`response.redirect().back()` in `/edit-mode`.** It relies on the Referer. Use named routes from the enum.
- **`bouncer.authorize()` in `/edit-mode`.** On Inertia requests it renders the forbidden page (`app/exceptions/handler.ts:92-106`), not a flash.
- **Storing `editMode: true` without the user id.** The session data survives logout and login (Pitfall 1).
- **Running `bunx shadcn add tooltip`** (Pitfall 5).
- **Redirecting `/learn` or the trash page** when the mode is on. That breaks « Aperçu », and the UI-SPEC restricts the switch to three pages.

## Common Pitfalls

### Pitfall 1: Edit mode survives logout and leaks to the next account
**What goes wrong:** UI-SPEC H4.5 says "Logout clears the session". It does not. `SessionGuard.logout()` only calls `session.forget(sessionKeyName)` (`node_modules/@adonisjs/auth/build/modules/session_guard/main.js:381-403`). `Session.regenerate()` only issues a new id and keeps the data (`@adonisjs/session/build/chunk-XP3CBOXR.js:344`).
**How to avoid:**
- Add `session.forget(EDIT_MODE_KEY)` in `AuthController.logout`. That honours D-14.
- Store `userId` in the flag and compare it on read. That covers the 2FA, OAuth and remember-me logins without touching them.
**Warning signs:** A functional test with `.withSession({ editMode: { userId: other.id, courseId } })` gets a builder redirect.

### Pitfall 2: The D-13 redirect traps editors (and admins on every course)
**What goes wrong:** With an unconditional "mode on + canEdit → redirect show to builder", these all land back in the builder:
- the builder's « ← Retour au cours » (`builder.tsx:862`);
- the learner view's « Retour au cours » (`learn.tsx:280, 435`);
- six controller redirects to `courses.show` (after update, publish, archive, …: `courses_controller.ts:139,227,255,269,288,308`; `course_contents_controller.ts:123`).

The course page holds « Publier », « Paramètres », the Participants tab and permission management (`show.tsx:271-500`), and none of them is reachable while the mode is on. `CoursePolicy.before` makes admins editors of every course, so an admin with the mode on can open no course page at all.
**How to avoid:** Redirect only when the course differs from the last one opened in edit mode (`state.courseId !== course.id`). The builder updates that id. This matches D-13's wording "opening **another** course". It needs an owner OK (Open Question 1).
**Warning signs:** A browser test clicks « Retour au cours » in the builder and asserts the URL `/courses/:id`.

### Pitfall 3: 403 page instead of flash on a refused toggle
**What goes wrong:** `authorize()` throws `E_AUTHORIZATION_FAILURE`. The handler renders `errors/forbidden` for Inertia requests (`handler.ts:96-106`), and the user loses the page.
**How to avoid:** Use `denies()` + `session.flash('error', …)` + redirect. The route's role middleware still returns a real 403 to students (the two-layer rule). Note: the UI-SPEC's interaction step 1 says "returns 403", while its States table says "flash error". The flash version is the user-facing one.

### Pitfall 4: Seeder creates a duplicate `/admin` row
**What goes wrong:** UI-SPEC H3 says "updateOrCreate the `/admin/settings` item to `/admin`". A `/admin` row already exists (`menu_seeder.ts:177`), so updating the old row's url gives two `/admin` rows. A reseed would then recreate `/admin/settings` (search key `{url:'/admin/settings'}` missing → create).
**How to avoid:** `MenuItem.query().where('menuId', userMenu.id).where('url', '/admin/settings').delete()` and remove its `updateOrCreate` block. Then update the existing `/admin` block's label and icon.

### Pitfall 5: shadcn CLI output does not compile here
**What goes wrong:** `components.json` aliases are `inertia/lib/utils` (a path), while every hand-made ui file imports `~/lib/utils`. The current shadcn CLI may also resolve the Tailwind v4 registry (`new-york-v4`), whose tooltip imports `{ Tooltip } from "radix-ui"` (the monopackage, not installed) and uses `animate-in`/`slide-*` classes that do not exist in `app.css`.
**How to avoid:** Hand-write the file from the official `new-york` source (code example below). Use `~/lib/utils`, swap in the UI-SPEC's whitelisted classes, and optionally add the existing `.animate-tooltip` class (`app.css:558`).

### Pitfall 6: Header search over 100 characters fails silently
**What goes wrong:** `courseIndexQueryValidator` caps `search` at `maxLength(100)` (`app/validators/course_admin.ts:20`). A longer query from the header fails validation and the request bounces back.
**How to avoid:** Add `maxLength={100}` on the header `Input`. Trim the value client-side before `router.get('/courses', { search })`.

### Pitfall 7: Tests that look for `h1` and header height assumptions
- `user_management.spec.ts:21,97` uses `page.assertTextContains('h1', …)`. Today the header `<h1>` comes first in the DOM, so turning it into a `<span>` makes these tests more reliable. Nothing else relies on the header h1. `navigation.spec.ts:51` only checks that a `header` element exists.
- `navigation.spec.ts` asserts `a[href="/admin/users"]` on `/dashboard`. That link comes from `dashboard.tsx:127`, not from the header, so it is unaffected.
- No test asserts « Réglages de la plateforme » or `SlidersHorizontal`. `accessibility.spec.ts:288` visits `/admin/settings` directly.
- `learn.tsx` sizes its body with `h-[calc(100vh-64px)]`. The UI-SPEC's fixed `h-16` row matches that, while today's `py-4` row only approximated it.
- `builder.spec.ts:180` tolerates "the app header's own hydration warnings". Do not add new ones: no `window` or `matchMedia` reads during render.

### Pitfall 8: Course collaborator with a student role
**What goes wrong:** `CoursePolicy.edit` can pass for any user who holds an `edit` `course_permission`, including one whose role is student. The builder route and `/edit-mode` require role admin|manager|teacher, so the switch would show and then 403.
**How to avoid:** Accept this edge as it is today: the builder already behaves the same way. Optionally compute `canEdit` as policy && role in the three controllers. Document whichever option is chosen; do not hide it.

### Pitfall 9: SETTINGS-01 wording
SETTINGS-01 (complete) says settings open "from an admin-only item of the user menu". Replacing that item with « Administration du site » changes how users reach a shipped requirement. The settings page is now one click deeper, through the hub. Have the orchestrator amend SETTINGS-01's wording, or keep both items (D-17 allows either).

## Open Questions

1. **D-13 scope (owner call).**
   - What we know: an unconditional redirect makes course pages unreachable for editors while the mode is on (Pitfall 2).
   - Recommendation: redirect only when opening a course other than the last one used in edit mode. Returning to the same course's page from its builder shows the page with the switch checked. Without that clause, the builder's and learner view's « Retour au cours » links do nothing useful while the mode is on. If the owner wants strict Moodle behaviour, drop the `courseId` clause and accept that.
2. **Keep « Réglages de la plateforme » in the avatar menu?** UI-SPEC recommends replacing it. SETTINGS-01's wording then needs a small amendment (Pitfall 9).
3. **Off from `/learn?content=X`** returns to `/learn` without `content`, which loses the position. Accept, or add an optional `contentId` to the validator. Recommendation: accept, since it is rare and the learner view reopens at the first content.

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Open redirect via the toggle | Spoofing | Named routes from the `from` enum; never `back()` or a client URL |
