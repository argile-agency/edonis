## Design System

| Property | Value |

| Tool | shadcn (`components.json` present, style `new-york`, baseColor `zinc`, CSS variables) |

| Font | Inter Variable (body), Source Serif 4 Variable (h1–h6), unchanged |

**One new shadcn component:** `tooltip` (official registry), added with `bunx shadcn@latest add tooltip`. It adds `@radix-ui/react-tooltip`, from the same family as the 12 Radix packages already installed. It is needed because D-01 requires a « Bientôt disponible » tooltip, and the browser's `title` attribute is not reachable by keyboard or touch. Everything else reuses `inertia/components/ui/`: `button`, `input`, `switch`, `label`, `tabs`, `separator`, `avatar`, `dropdown-menu`.

**Tooltip restyle (class whitelist rule, 05.2).** `app.css` hand-writes its colour utilities, and `tw-animate-css`/`tailwindcss-animate` are not installed. Replace the generated `TooltipContent` classes with:
`z-[110] overflow-hidden rounded-md border bg-popover px-2 py-1 text-xs text-popover-foreground shadow-md`
Both `bg-popover` (app.css l.261) and `text-popover-foreground` (l.331) exist. Do not use `bg-primary` (filled tooltips would take the accent), `animate-*` or `data-[side]:slide-*` classes. `z-[110]` matches `DropdownMenuContent` and sits above the sticky header (`z-50`). One `<TooltipProvider delayDuration={300}>` wraps the header's content.

## H1 — Desktop header layout (≥ `lg`)

**Focal point.** The filled « Tableau de bord » button (the only filled teal element for signed-in users) anchors the header; the icon buttons are ghost and recede. On `/admin`, the h1 « Administration du site » and the first section heading (« Réglages de la plateforme ») anchor the page.

```
<header class="border-b sticky top-0 z-50 shadow-sm" bg = hsl(var(--background))>   (unchanged shell)
  skip link · TermsConsentBanner · FlashMessages                                       (unchanged)
  <div class="container mx-auto px-4 h-16 flex items-center gap-6">
    [brand]  Link "/" flex items-center gap-2 shrink-0
             logo img h-8 | GraduationCap h-8 w-8
             app name  text-lg font-bold   → `hidden xl:inline` when a user is signed in (see width budget)
    [nav]    <nav aria-label="Navigation principale" class="hidden lg:flex items-center gap-6">
             header menu links (text-sm font-normal hover:text-primary; was font-medium)
             « Tableau de bord » Button size="sm" (filled, D-08, unchanged)       signed in only
    [zone]   <div class="ml-auto flex items-center gap-1">                         user zone, D-07 order
             wrench* · search* · theme · bell* · messages* · avatar+caret* · edit-mode*
             (* signed in only; wrench admins only; edit-mode per H4)
    [☰]      hamburger Button, `lg:hidden`, last item in the row
  </div>
</header>
```

- The `<h1>` around the app name becomes a `<span>`. A page has one h1 (its title), and the header repeats on every page. When the name is visually hidden below `xl`, the `Link` keeps an accessible name: the logo `img` alt carries the app name, and the `GraduationCap` fallback gets `aria-hidden` with the name kept in an `sr-only` span.
- Row height is fixed at `h-16` (64px), replacing `py-4`, so the bar does not jump when the search field opens or the switch appears.
- Between the avatar and the edit-mode block there is a vertical divider: `<Separator orientation="vertical" className="h-6 mx-2" />`, shown only when the edit-mode block renders. It mirrors Moodle's split between the user menu and the editing switch.

### Width budget (worst case: admin, in the builder, `lg` = 992px of content)

| Block | Approx. width |
|---|---|
| Logo only (name hidden below `xl`) | 32px |
| Nav: « Accueil », « Cours » and the « Tableau de bord » button, gap-6 | ~300px |
| 5 icon buttons at 36px + gap-1 | ~200px |
| Avatar + caret | ~56px |
| Divider + « Mode d'édition » label + switch | ~170px |
| Gaps between blocks (gap-6 × 3) | 72px |
| **Total** | **~830px**, which fits in 992px |

Rules that keep the single row from breaking:
1. **Below `lg` (< 1024px)** the nav and admin and edit-mode items move into the hamburger panel (H5).
2. **`lg`–`xl`**: signed-in users see the logo without the app name. Signed-out visitors have only three zone items, so they keep the name.
3. **The open search field (192px) hides the nav below `xl`**: while the search is open, `<nav>` gets `hidden xl:flex`. It comes back when the search closes. At `xl` (1280px) and above, everything fits with the field open.
4. Header menu items come from the admin-editable menu. More than three links is not a supported case in v0.1: the nav gets `overflow-hidden` so extra links clip instead of wrapping. Below `lg` they all show in the panel.

## H2 — User-zone icon buttons

All icon buttons share one style, matching the existing `ThemeToggle`: `Button variant="ghost" size="icon" className="h-9 w-9 rounded-full"`. The glyph is `h-5 w-5` with `aria-hidden="true"`. They use **no accent colour** (ghost, `text-foreground`, shadcn hover `bg-accent/…` as today).

| Order | Item | Element | Accessible name | Tooltip | Who sees it |
|---|---|---|---|---|---|
| 1 | Admin | `<Link href="/admin">` via `Button asChild`, `Wrench` | « Administration du site » (`aria-label`) | Administration du site | admins (`roles.some(slug === 'admin')`), ≥ `lg`; below `lg` it is in the panel |
| 2 | Search | `<button>`, `Search`, `aria-expanded`, `aria-controls="header-search"` | « Rechercher des cours » | Rechercher des cours | signed in (D-15) |
| 3 | Theme | existing `ThemeToggle` (dropdown Clair / Sombre / Système), add `rounded-full` | « Changer le thème » (existing sr-only) | none (dropdown trigger) | everyone, every width |
| 4 | Notifications | `<button aria-disabled="true">`, `Bell` | « Notifications (bientôt disponible) » | Bientôt disponible | signed in |
| 5 | Messages | `<button aria-disabled="true">`, `MessageSquare` | « Messages (bientôt disponible) » | Bientôt disponible | signed in |

**Placeholders (D-01).** Do **not** use the `disabled` attribute. `button.tsx` applies `disabled:pointer-events-none`, and native `disabled` removes keyboard focus, so neither hover nor focus could open the tooltip. Instead:
- `aria-disabled="true"`, `onClick` is a no-op (`e.preventDefault()`), no navigation.
- Dimmed with `opacity-50 cursor-not-allowed`. Hover keeps no background change: add `hover:bg-transparent` (a core Tailwind utility, not a theme colour, so it generates).
- They stay in the tab order, and the tooltip opens on hover and on keyboard focus (Radix default).
- No badge or count dot.

**Search (D-15).**
- Closed: the magnifier button only.
- Open: the button is replaced in place by
  `<form role="search" id="header-search" onSubmit={…} class="flex items-center">` containing
  `<Input type="search" name="search" aria-label="Rechercher des cours" placeholder="Rechercher un cours…" class="h-9 w-48 rounded-full" autoFocus />`.
  There is no visible submit button; Enter submits. 192px wide.
- Submit: if the trimmed value is non-empty, `router.get('/courses', { search: value })` and the field closes. An empty value does nothing. The existing `courses/index.tsx` already prefills its own search field from `filters.search` and shows its existing empty state « Aucun cours trouvé ».
- Close: Escape closes the field and returns focus to the magnifier button. Blur with an empty value closes it. Blur with text keeps it open, so a misclick does not lose the query. Inertia navigation closes it.
- Visitors: not rendered (`/courses` requires auth).

## H4 — « Mode d'édition » switch (D-11..D-14)

**Where.** Last item of the user zone, ≥ `lg`. Below `lg`, it is in the hamburger panel. It renders only when **all** of these hold:
- the page is `courses/show`, `courses/learn` or `courses/builder`. The trash page `/courses/:id/trash` and every other page do **not** show it, following D-11's list.
- the current user passes `CoursePolicy.edit` for that course. Students never see it.

**Markup.**
```
<div class="flex items-center gap-2">
  <Label htmlFor="edit-mode-switch" class="text-sm font-normal whitespace-nowrap cursor-pointer">Mode d'édition</Label>
  <Switch id="edit-mode-switch" checked={enabled} disabled={processing} onCheckedChange={toggle} />
</div>
```
The label is visible and verbatim « Mode d'édition » (specifics). The accessible name comes from the `<Label>`, and Radix gives `role="switch"` and `aria-checked`. The checked track is `--primary`, which is the existing `switch.tsx` style.

**Data to the header.** The header reads with `usePage().props`. No new prop is threaded through `AppLayout` or the pages:
- Shared prop `editMode: boolean` from the session flag (D-14), added to `config/inertia.ts` `sharedData` next to `auth`, wrapped in `inertia.always`. It is `false` for visitors.
- Page prop `courseEditing: { courseId: number, canEdit: boolean }`, sent only by `CoursesController.show`, `CourseContentsController.learn` and `CourseContentsController.builder`. It is computed with the existing policy (`bouncer.with(CoursePolicy).allows('edit', course)`). The switch renders when `courseEditing?.canEdit === true`.

**Interaction.**
1. Toggle → `router.post('/edit-mode', { enabled: next, courseId })`. It is one small endpoint, auth only. The server re-checks `CoursePolicy.edit` on `courseId` and returns 403 otherwise. It sets `session.put('editMode', enabled)` and redirects:
   - **on** → `/courses/:id/builder` (D-12).
   - **off**, from the builder → `/courses/:id/learn` (D-12).
   - **off**, from the course page or the learner view → back to the same page (`response.redirect().back()`). Nothing else changes on those pages.
   The client cannot tell which page it is on server-side, so the post also sends `from: 'builder' | 'show' | 'learn'`. The server maps it with a whitelist and never redirects to a client-supplied URL.
2. While the request is in flight the switch is `disabled` (one `processing` state) and the click target gets `aria-busy="true"`. There is no optimistic flip: the page changes anyway.
3. **Persistence across courses (D-13).** While `editMode` is on, `CoursesController.show` redirects to `/courses/:id/builder` when the user can edit that course. **Only `show` redirects.** `/learn` never redirects, so the builder's « Aperçu » link and the course page's « Aperçu étudiant » keep working while the mode is on. In the learner view the switch shows **checked**. Turning it off there leaves the user on `/learn` (rule 1).
4. Courses the user cannot edit: no redirect, no switch, and the flag stays as it is.
5. Logout clears the session, so the mode resets (D-14).
6. Error: 403 or 404 on the post → the existing flash error, the switch reverts to the server value after the redirect. A network error uses the Inertia default.

## H5 — Mobile / tablet header (< `lg`) (D-09)

**Bar, signed in:** brand (logo + app name, name `hidden sm:inline` so a 360px phone fits) · `ml-auto` · theme · bell · messages · avatar+caret · ☰.
Bell and messages stay in the bar, as D-09 requires. The theme toggle also stays in the bar: it is a single 36px icon and visitors need it. Estimate at 360px: logo 32 + 5 × 36 + avatar 56 + gaps ≈ 300px, which fits.

**Hamburger.** `Button variant="ghost" size="icon" className="h-9 w-9 rounded-full lg:hidden"`, icon `Menu`, or `X` when the panel is open.
- `aria-label`: « Ouvrir le menu » when closed, « Fermer le menu » when open; `aria-expanded`; `aria-controls="mobile-menu"`.

**Panel.** A plain disclosure, not a dialog. No new component, no focus trap.
```
<div id="mobile-menu" class="lg:hidden border-t bg-[hsl(var(--background))]" hidden={!open}>
  <div class="container mx-auto px-4 py-4 flex flex-col gap-4">
    search form (signed in)  — same form as H2, always expanded, `w-full`, no autofocus
    <nav aria-label="Navigation principale (mobile)" class="flex flex-col">
      header menu links  — `py-2 text-sm font-normal`, each a 40px touch target
    </nav>
    « Tableau de bord » Button size="sm" filled, `w-full sm:w-auto`    (signed in)
    <Separator />                                                       (only if any item below renders)
    « Administration du site » link with Wrench icon, `py-2 text-sm font-normal`   (admins)
    « Mode d'édition » label + Switch, `flex items-center justify-between py-2`   (H4 conditions)
  </div>
</div>
```
- The panel pushes the page content down inside the sticky header. It is not an overlay.
- Escape closes the panel and returns focus to ☰. Clicking ☰ again closes it. Every Inertia navigation closes it (`router.on('navigate')` or a `usePage().url` effect). Resizing to ≥ `lg` hides it through `lg:hidden`.
- The panel's switch uses `id="edit-mode-switch-mobile"` so the two ids never collide. Only one instance is visible at a time, but both are in the DOM.

Analog: `inertia/pages/admin/settings.tsx` (tabs, `AppLayout width="narrow"`).

```

      TabsTrigger "general"  « Général »       (Settings2/SlidersHorizontal icon h-4 w-4 aria-hidden, class gap-2)
      TabsTrigger "users"    « Utilisateurs »  (Users icon)
      TabsTrigger "courses"  « Cours »         (BookOpen icon)

    <TabsContent value="…">
      one <section aria-labelledby="admin-{tab}-{n}"> per group, separated by <Separator />:
```

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (nav links, panel rows, switch label, hub links, hub intro) | 14px (`text-sm`; the hub intro sets `text-sm` explicitly) | 400 | 1.43 (`text-sm` 14/20) |
| Label (tooltip, avatar menu email) | 12px (`text-xs`) | 400 | 1.33 (`text-xs` 12/16) |
| Heading (hub section h2; header app name) | 18px (`text-lg`) | 700 (`font-bold`) | 1.56 (`text-lg` 18/28) |
| Display (hub h1) | 30px (`text-3xl`) | 700 (`font-bold`) | 1.2 (`text-3xl` 30/36) |

Exactly **4 sizes** (12, 14, 18, 30) and **2 weights** (400, 700), the 05.1/05.2 pair. The header app name moves from `text-xl` (20px) to `text-lg` (18px, `font-bold`), sharing the Heading row.

**Primitives that hard-code `font-medium` (500).** `Button`, `TabsTrigger` and `Label` (shadcn files) are **not edited**: every other page uses them. Instead, every instance this phase renders or touches passes a weight override through `className`, and `cn()` (tailwind-merge) drops the primitive's `font-medium`:
- `font-normal`: header nav links, mobile panel rows, the admin link in the panel, the « Mode d'édition » `Label`, hub `TabsTrigger`s (the active tab is shown by its background and shadow, not weight), hub links.
- `font-bold`: the « Tableau de bord », « Connexion » and « Inscription » header buttons (filled/outline CTAs keep emphasis), the app name, hub h1 and h2.
- Avatar menu items keep the `DropdownMenuItem` default (400). The identity name in the menu label changes from `font-medium` to `font-bold`.
No `font-medium` or `font-semibold` class appears in markup written for this phase.

## Keyboard and screen reader

- Tab order follows the visual order: skip link → brand → nav → wrench → search → theme → bell → messages → avatar → switch → ☰.
- Every icon-only control has a French accessible name (H2 table, hamburger). Every lucide glyph is `aria-hidden="true"`.

## Open questions / defaults chosen

Defaults the planner may follow. None of them reopens a locked decision.

1. **Tooltip dependency.** The shadcn `tooltip` adds `@radix-ui/react-tooltip`. It is required by D-01 (« Bientôt disponible » tooltip): the native `title` fails keyboard and touch users. Placeholders use `aria-disabled`, not `disabled`, so they can be focused.
2. **Collapse breakpoint is `lg`** (not `md`). The worst case (admin in the builder) needs about 830px. Below `xl`, signed-in users see the logo without the app name, and the open search field hides the nav.
3. **Edit-mode redirect scope (D-13).** Only `CoursesController.show` redirects to the builder. `/learn` never redirects, so the « Aperçu » buttons keep working while the mode is on.
4. **Turning edit mode off outside the builder** keeps the user on the current page. D-12 only defines « off » from the builder.
5. **Trash page** (`/courses/:id/trash`) shows no switch, following D-11's list.
6. **Data path.** `editMode` is a shared prop (session). `courseEditing { courseId, canEdit }` is a page prop from the three course controllers, read by the header through `usePage()`. `AppLayout` and the page components do not change. The toggle endpoint whitelists `from` and never redirects to a client URL.
7. **Avatar menu.** « Réglages de la plateforme » is replaced by « Administration du site » (D-17, planner's call, recommended). The disabled « Messages personnels » gains « (bientôt disponible) ».
8. **Mobile panel** is a plain disclosure that pushes content down (no Sheet, no focus trap). It closes on Escape and on navigation. The theme toggle, bell, messages and avatar stay in the phone bar. « Tableau de bord », the admin link and the switch move into the panel.
9. **Visitors on mobile.** « Inscription » moves into the panel; « Connexion » stays in the bar.
10. **Search empty submit** does nothing. Blur with text keeps the field open.
11. **Hub link map** adds two items beyond D-16's starting map: « Créer une catégorie » and the five settings sub-links (D-16 allows both). The « Créer un cours » link points to `/courses/create`, the only create route.
12. **Hub tab not in the URL.** Local Radix state, default « Général ». Deep links to a hub tab are deferred.
13. **Header `<h1>` becomes a `<span>`.** Every page already has its own h1, and a repeated h1 in the header breaks the heading outline.
14. **Caret rotation** relies on a `group-data-[state=open]` variant. If it does not generate under the hand-written `app.css`, it is dropped and the caret stays static.
