## Deviations from Plan

1. **[Rule 1 - Bug] Account menu trigger failed axe `label-content-name-mismatch`** (118057e).
   - Found during: Task 2.
   - Issue: `aria-label="Menu du compte"` did not contain the visible initials. Every signed-in page failed, including the existing dashboard and builder cases.
   - Fix: replaced the aria-label with sr-only text and marked the trigger's Avatar `aria-hidden`. The accessible name is unchanged.
2. **[Rule 3 - Blocking] Login throttle in browser groups.**
   - The per-IP `loginThrottle` (5/min) lives in the test process's memory store, so a group with several logins gets 429 responses.
   - Added `group.each.setup(() => limiter.clear())` to the Header and Accessibility groups, following the precedent in `tests/functional/two_factor.spec.ts`.
3. **[Rule 3 - Blocking] Success toast over the header.**
   - « Connexion réussie » covers the user zone, and sonner pauses while hovered, so clicks timed out.
   - The login helpers reload after login.
4. **Search test data.** The search case creates its own course with a unique title through `createCourse(admin)` instead of using a seeded title, so it does not depend on seed content. The course is deleted in `finally`.
5. **Worktree setup (not committed).**
   - Fast-forwarded from b9888ef to the base 7607edd.
   - Copied `.env`, ran `bun install`, and ran `npm rebuild better-sqlite3` under Node 22.
   - Downloaded Chromium 1248 for the pinned Playwright.
   - Migrated and seeded `tmp/test.sqlite3`.

### What changed

- **Theme tokens (`inertia/css/app.css`).** Hues are unchanged; only lightness moved.
  - Light: `--primary` 32% → 28%, `--muted-foreground` 45% → 40%, `--success` 40% → 30%, `--destructive` 55% → 48%.
  - Dark: `--primary-foreground` and `--success-foreground` → `20 15% 10%` (dark text).
  - `--ring` is unchanged.
- **Sonner `richColors`, light theme.** The status texts are overridden in an unlayered rule so they beat the styles sonner injects. Sonner's defaults measured 3.1–4.4:1; the dashboard « Connexion réussie ! » toast failed.
- **Status badges** (`courses/index`, `courses/show`, `courses/learn`).
  - `getStatusVariant` replaces `getStatusColor`: published → `success`, draft → `warning`, archived → `secondary`, other → `outline`.
  - The `bg-*` utilities these variants use are written in app.css (05.2 whitelist rule).
- **Tabs.** No component change; they pass once `--muted-foreground` is darker.
- **Accessible names.**
  - Password toggles: « Afficher / Masquer le mot de passe », and « … la confirmation du mot de passe » on the second register field.
  - Avatar input: `id="avatar"` with an sr-only « Choisir une photo de profil » label.
  - Course filters: « Filtrer par statut » and « Filtrer par catégorie ».
- **Builder actions menu.** It is now `modal={false}`, so Radix no longer `aria-hidden`s the page while focusable controls stay inside it.
  - `onFocusOutside` is prevented. Without that, builder refocus after a save closed the menu, which broke the `builder.spec` delete/undo case. It passes again.
- **Axe timing.** Many of the 05.3-05 contrast reports were measured mid-fade.
  - The layout fades `body` in on `fonts-loaded` (0.2s), and the toasts animate in. Axe then read lighter blended colours, for example #3a837c instead of #1e7169.
  - `analyze(page)` waits until no finite animation is running, then runs axe.
  - The accessibility, builder_bulk and builder_trash specs use it.
