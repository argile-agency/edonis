    Add three module-level type guards near the top of `app/exceptions/handler.ts`, below the
    imports and outside the class body:

    - type `ErrorWithCode = { code: string }` with `function hasCode(error: unknown): error is ErrorWithCode`
    - type `ErrorWithStatus = { status: number }` with `function hasStatus(error: unknown): error is ErrorWithStatus`
    - type `ErrorWithHeaders = { headers: Record<string, string | undefined> }` with
      `function hasHeaders(error: unknown): error is ErrorWithHeaders`

    Each guard checks `typeof error === 'object' && error !== null` and then the `typeof` of the
    specific property (`'string'` for `code`, `'number'` for `status`, `'object'` plus a non-null
    check for `headers`). Inside the guard bodies a single localised assertion to the guard's own
    shape is acceptable ESLint-wise only if it is not `any` — use the named type
    (e.g. `(error as ErrorWithCode).code`), never `as any`.

    Then rewrite the five call sites:
    - Lines 28-29 (`retryAfter` in the `'429'` renderer): gate on `hasHeaders(error)`, read
      `error.headers['retry-after']`, pass it through `Number.parseInt(... ?? '', 10) || undefined`,
      and fall back to `undefined` when the guard fails.
    - Line 75 and line 211: replace `(error as any)?.code ?? ''` with `hasCode(error) ? error.code : ''`.
    - Line 109: replace `(error as any)?.status ?? 500` with `hasStatus(error) ? error.status : 500`.

    Do NOT import `@adonisjs/limiter` to do an `instanceof ThrottleException` check — the package
    exposes no `./errors` export subpath, so that would pull the whole limiter into the HTTP error
    handler purely for a type test.

    **Security constraint (V7 Error Handling):** line 11, the class field declaration
    `protected debug = !app.inProduction`, must remain byte-identical and must not move.
    Do not add a `this.debug = ...` assignment anywhere — the field declaration is the gate, and
    introducing an assignment would itself be a change to it.
    This change narrows types only; it must not widen what is disclosed
    to a client, must not add any new field to the Inertia props passed to `errors/server_error`,
    and must not move any stack/frame data outside the existing `this.debug` gate.

    **Behavioural note for the commit message (not a bug, but a real delta):** today
    `(error as any)?.code` yields whatever `.code` holds, and the subsequent `.toLowerCase()` would
    *throw* if `code` were a non-string. The guarded version yields `''` instead, so it cannot throw.
    This is strictly safer, but it is a change — state it explicitly in the commit body rather than
    letting it ship silently as "just types".
  </action>
