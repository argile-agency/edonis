<objective>
Fix Cluster D: `Course.canEnroll()` passes a Luxon `DateTime` to
`DateTime.fromJSDate()`, which expects a JS `Date`. The result is an **invalid**
DateTime whose `valueOf()` is `NaN`, so both comparisons have always evaluated
`false`. **Enrollment date windows have never been enforced in this product.**

Purpose: this is the only genuine runtime bug hidden behind an `as any` in this
phase, and the only behaviour change in Phase 1. `canEnroll` is serialized by
`Course.serialize()` and consumed by `inertia/pages/courses/index.tsx` and
`show.tsx`, so users currently see an enrol affordance on courses that have not
started or have already ended. Fixing the type fixes the behaviour — visibly.

Output: a two-line correction in `app/models/course.ts`, a new `tests/unit/`
suite that proves the window is enforced, and a human-confirmed data check of
how many existing `courses` rows change eligibility.
</objective>

From `node_modules/luxon/src/datetime.js:687`:
- `DateTime.fromJSDate(date)` runs `const ts = isDate(date) ? date.valueOf() : NaN`
- `isDate()` is an `[object Date]` brand check — a Luxon `DateTime` FAILS it
- `NaN` → `DateTime.invalid("invalid input")` → `valueOf() === NaN` → every comparison is `false`

Measured against this project's own luxon@3.7.2:
    DateTime.fromJSDate(aDateTime).isValid        = false
    CURRENT  (fromJSDate(start) > now)            = false   <-- guard intended TRUE
    CORRECT  (start > now)                        = true
    CURRENT  (fromJSDate(end)   < now)            = false   <-- guard intended TRUE
    CORRECT  (end   < now)                        = true

From `app/models/course.ts` lines 51-55:
    @column.date()
    declare startDate: DateTime | null
    @column.date()
    declare endDate: DateTime | null

Luxon `DateTime` supports `>` / `<` natively via `valueOf()` → epoch millis.

Japa suite config (`adonisrc.ts`): suite `unit`, glob `tests/unit/**/*.spec(.ts|.js)`,
timeout **2000ms**. The `assert()` plugin is already registered in `tests/bootstrap.ts`.
`tests/unit/` does not exist yet and must be created.
