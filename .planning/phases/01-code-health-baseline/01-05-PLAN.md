<objective>
Turn Phase 1's two unfalsifiable CI gates into real ones.

Today `.github/workflows/ci.yml` sets `continue-on-error: true` on the ESLint step,
so lint failures do not fail CI — "green CI" is a claim CI cannot falsify. And the
test step is `node ace test functional || echo "No functional tests found yet"`,
where the `|| echo` makes the shell exit 0 regardless, so `continue-on-error: false`
on that step is irrelevant.

Purpose: plans `01-01` through `01-04` make `bun run lint`, `node ace test unit` and
`node ace test functional` meaningful locally. This plan is what makes them
*enforced*. Without it, every other criterion in this phase is advisory.

Output: an ESLint step that can fail the build, separate enforced unit and functional
test steps with no `||` escape, a correctly named job, and a demonstrated red→green
CI transition.
</objective>

Current `.github/workflows/ci.yml` defects:
- job `lint-and-typecheck`, step "Run ESLint": `run: bun run lint` followed by `continue-on-error: true`
- job `unit-tests`, step "Run unit tests":
  `run: node ace test functional || echo "No functional tests found yet"` with `continue-on-error: false`
  -> the `|| echo` makes the SHELL exit 0, so the step-level flag never gets a chance to matter
- the job is named `unit-tests` / "Unit Tests (${{ matrix.db }})" but runs the **functional** suite
- job `summary` declares `needs: [lint-and-typecheck, build, security-audit, unit-tests]` and echoes
  `${{ needs.unit-tests.result }}` — both must be updated if the job is renamed

Measured: `node ace test functional` on an EMPTY suite prints `NO TESTS EXECUTED` and exits **0**.
Removing the `|| echo` alone is therefore necessary but not sufficient — plan `01-03` supplies the
real tests, and this plan must assert a non-trivial pass count.

What already works in CI and must NOT be disturbed:
- `services: postgres:16` / `mysql:8.0`, the `db: [postgres, mysql, sqlite]` matrix, and the
  per-leg `db_connection` / `db_host` / ... `include` entries
- the `mkdir -p tmp` (SQLite) step, `node ace migration:run --force`, and `node ace db:seed`
- the job-level `env:` block (`DB_*`, `NODE_ENV: test`, `APP_KEY`, `PORT`, `HOST`, `LOG_LEVEL`,
  `SESSION_DRIVER`)

Interaction with the new committed `.env.test` (from plan `01-03`): AdonisJS env resolution gives
an already-present `process.env` value precedence over every dotenv file
(`node_modules/@adonisjs/env/build/index.js:227`). The CI job-level `env:` block therefore still
wins over `.env.test`, and the three-database matrix remains meaningful. Confirm this empirically
in Task 3 rather than assuming it.

Current `package.json` scripts: `lint` = `eslint .`, `typecheck` = `tsc --noEmit`,
`test` = `node ace test`. There is no combined static-gate script.

Suites: `unit` (`tests/unit/**`, created by plan `01-02`), `functional` (`tests/functional/**`,
built by plan `01-03`), `browser` (covered separately by `e2e.yml` — out of scope here).

Suite-ordering contract inherited from plan `01-03`: `testUtils.db().migrate()` returns a teardown
that runs **`migration:reset`** (a full schema drop). `01-03` therefore registers that hook on the
`functional` suite only, via `configureSuite`, never runner-globally. Running `unit` before
`functional` in the same job is safe *because of that scoping* — Task 1 re-verifies it rather than
assuming it.

Note the `build` job produces the Vite manifest but its artifact is **never downloaded** by the
tests job, so `public/assets/.vite/manifest.json` is absent during the test run. Plan `01-03`
guarantees no functional test triggers a full-HTML render, so no manifest is required. Do not add
a build or artifact-download step to the tests job in this plan.

| CI job `env:` -> committed `.env.test` | If the precedence were reversed, all three matrix legs would silently collapse onto sqlite |
