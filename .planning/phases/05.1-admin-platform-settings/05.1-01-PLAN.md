- **D-11 / D-15 validator design (Claude's discretion: one validator per tab):**
  - `export const SETTINGS_TABS = ['appearance', 'home', 'access', 'contact'] as const` and `export type SettingsTab = (typeof SETTINGS_TABS)[number]`.
  - Shared metadata: `vine.withMetaData<{ appHost: string }>()` on every compiled validator; the controller passes `{ meta: { appHost: request.host() ?? '' } }`.
  - Custom rule `imageUrl` (`vine.createRule`): accepts a root-relative path matching `^/(?![/\\])[^\s\u0000-\u001f\u007f]*$` (rejects `//host` and `/\host`, which browsers treat as protocol-relative, whitespace and control characters), or an absolute URL parsed with `new URL()` whose `protocol` is `http:`/`https:` AND whose `host` equals `field.meta.appHost` (same origin, port included). Anything else → `field.report(messages.imageUrl, 'imageUrl', field)`. Reason: CSP `imgSrc` is `'self' data: blob:` and stays unchanged (D-15 default).
  - Custom rule `linkUrl` with option `{ allowPath: boolean }`: absolute URL with protocol `http:`/`https:` (parsed with `new URL()`; `javascript:`, `data:`, `mailto:` and every other scheme refused); when `allowPath`, the same root-relative path regex as above is also accepted.
  - `appearance`: `appName` string trim maxLength(100) required; `appLogoUrl`, `appFaviconUrl` string trim maxLength(255) `.use(imageUrl())` optional nullable; `primaryColor` string trim `regex(/^#[0-9a-f]{6}$/i)` then `toUpperCase()`, required.
  - `home`: `heroTitle` trim maxLength(150) required; `heroSubtitle` trim maxLength(300) optional nullable; `heroImageUrl` as the logo; `announcementText` trim maxLength(280) optional nullable.
  - `access`: `allowRegistration` `vine.boolean()` required.
  - `contact`: `contactEmail` trim maxLength(254) `email()` optional nullable; `supportUrl` trim maxLength(255) `.use(linkUrl({ allowPath: true }))` optional nullable; `socialLinks` `vine.object({ facebook, twitter, linkedin, github })` each trim maxLength(255) `.use(linkUrl({ allowPath: false }))` optional nullable (unknown keys dropped by VineJS default).
  - `export const appSettingValidators: Record<SettingsTab, ...>` mapping tab → compiled validator.
  - Empty strings: `config/bodyparser.ts` has `convertEmptyStringsToNull: true`, so `''` arrives as `null`. The schema is still nullable/optional for every non-required field; a required field receiving `null` reports `required`.
  - French messages (UI-SPEC "Field error messages"), one `SimpleMessagesProvider` assigned to each compiled validator's `messagesProvider`: `required` « Ce champ est obligatoire. », `maxLength` « Ce champ ne doit pas dépasser {{ max }} caractères. », `primaryColor.regex` « Saisissez une couleur au format #RRGGBB (ex. #5046E5). », `email` « Saisissez une adresse e-mail valide (ex. contact@exemple.org). », `linkUrl` « Saisissez une adresse commençant par https:// ou http://. », `imageUrl` « Saisissez un chemin commençant par / ou une adresse de ce site. Les images d'un autre domaine sont bloquées. », `boolean` « Valeur invalide. ». Export the message strings as named constants (`IMAGE_URL_MESSAGE`, `LINK_URL_MESSAGE`, `COLOR_MESSAGE`) so tests in this plan and 05.1-05 compare against them.
  - Not in any schema (D-04, D-05, D-10): `secondaryColor`, `accentColor`, `headerHtml`, `footerHtml`, `welcomeMessage`, `showStats`, `showPublicCourses`, `isActive`.
