### Gaps Summary

There are two small, independent gaps. Neither blocks the admin from using the page, but each breaks a written clause of the requirement:

1. **Blank required fields (SETTINGS-03, D-11).** `'   '` for app name or hero title is accepted and stored as NULL, which leaves an empty header title and hero. Fix: a non-blank rule after `trim()` plus tests.
2. **Logo and favicon not URL-guarded (SETTINGS-06).** The other admin-set URLs use `safe_url.ts`; these two do not. The risk is minimal (no script execution, CSP `imgSrc 'self'`).

The 05.1-03 plan chose this on purpose (« unchanged » header rendering, escape-only favicon). If the owner accepts it, add an override instead of fixing it:
