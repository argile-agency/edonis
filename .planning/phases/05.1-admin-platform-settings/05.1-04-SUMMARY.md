# Phase 05.1 Plan 04: Admin settings page Summary

The `/admin/settings` page is in `inertia/pages/admin/settings.tsx`. It has four Radix tabs (Apparence, Page d'accueil, Accès, Contact et support), each with its own `useForm` declared at page level and its own submit button. The active tab follows `?tab=` through `router.replace`. Every submit is a `PUT /admin/settings/:tab` with `preserveState: 'errors'`. Accessibility is wired by hand: each field has its help and error ids, `aria-describedby`, and `aria-invalid`; on error a toast appears and focus moves to the first invalid field.

## Implementation notes

- **Tab URL sync:** `router.replace` shipped. It has not been exercised at runtime yet, because the route only arrives in 05.1-05. Plan 05.1-05 (or the 05.1-06 walkthrough) must confirm that switching tabs rewrites the URL without a server request. If it misbehaves, switch to the fallback recorded in decisions.
- **Trade-off (recorded per plan):** a successful save redirects to `?tab=<tab>` and remounts the page. The forms re-initialise from fresh props and `FlashMessages` toasts again. Unsaved edits in other tabs are lost at that point.
- **Input caveat respected:** the `error` / `helperText` props of `Input` are never used. Help and error `<p>` elements are rendered by the local `Field` component, and `aria-invalid` / `aria-describedby` are passed explicitly.
- **Colour pair:** the `type="color"` picker gets a valid `#rrggbb` value (`#000000` while the text is mid-edit/invalid). The text input carries the label, `required`, and `maxLength=7`.
- **Logo preview:** an `<img alt="Aperçu du logo">` is shown when the URL is non-empty. On `onError` it is swapped for « Image introuvable à cette adresse. », and that state resets whenever the URL is edited.
- Nested errors are read from `contactForm.errors` cast to `Record<string, string | undefined>` (keys `socialLinks.facebook`, …). `idFor('socialLinks.x') → 'social-x'`.

## Deviations from Plan

### Auto-fixed / added

1. **[Rule 2 - a11y] Social inputs reference the shared help line.** The line « Réseaux sociaux : … » gets `id="social-help"`, and each social input's `aria-describedby` includes it, plus `social-<key>-error` when there is an error.
2. **Focus order:** the first invalid field is chosen in the tab's field order rather than by `Object.keys(errors)[0]`, with that key order as the fallback. This is more deterministic than relying on the server's key order.
3. **Literal ids:** the social ids are listed explicitly in `SOCIAL_FIELDS`, and the Switch's `aria-describedby` is written as literals. This keeps the acceptance greps meaningful and does not change behaviour.
