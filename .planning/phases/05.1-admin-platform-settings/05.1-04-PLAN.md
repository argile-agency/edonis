<!-- SETTINGS PAGE CONTRACT — identical copy in 05.1-04 and 05.1-05. Do not change one without the other. -->
- `GET /admin/settings` (route name `admin.settings`) → `inertia.render('admin/settings', { settings, activeTab })`, plus the shared props `auth`, `appSettings`, `menus`, `flash`.
- `settings` has exactly these keys: `appName: string`, `appLogoUrl: string | null`, `appFaviconUrl: string | null`, `primaryColor: string`, `heroTitle: string | null`, `heroSubtitle: string | null`, `heroImageUrl: string | null`, `announcementText: string | null`, `allowRegistration: boolean`, `contactEmail: string | null`, `supportUrl: string | null`, `socialLinks: { facebook: string | null; twitter: string | null; linkedin: string | null; github: string | null }` (always the four keys; stored `''` or missing keys are sent as `null`).
- `activeTab: 'appearance' | 'home' | 'access' | 'contact'`, from the `?tab=` query string, default `'appearance'` for missing or unknown values.
- `PUT /admin/settings/:tab` (route name `admin.settings.update`), `:tab` limited to the four values by a route `.where()` constraint (anything else is 404). The body carries only that tab's fields:
  - `appearance`: `appName`, `appLogoUrl`, `appFaviconUrl`, `primaryColor`
  - `home`: `heroTitle`, `heroSubtitle`, `heroImageUrl`, `announcementText`
  - `access`: `allowRegistration` (boolean)
  - `contact`: `contactEmail`, `supportUrl`, `socialLinks: { facebook, twitter, linkedin, github }`
  - empty inputs are sent as `''`; the body parser (`convertEmptyStringsToNull: true`) turns them into `null`, and the server stores `null`.
- Success: 302 to `/admin/settings?tab=<tab>` with flash `success` « Réglages enregistrés. », or « Aucune modification à enregistrer. » when nothing changed.
- Validation failure: VineJS redirects back (Referer) with field errors and no flash. Error keys equal the body keys; nested ones are `socialLinks.facebook`, `socialLinks.twitter`, `socialLinks.linkedin`, `socialLinks.github`. Messages are French (05.1-01).
- Non-admin: 403 (role middleware, JSON body); anonymous: 302 to `/login`.
<!-- END SETTINGS PAGE CONTRACT -->

Components (all existing, `inertia/components/ui/`): `tabs` (`Tabs`, `TabsList`, `TabsTrigger`, `TabsContent`, Radix), `card` (`Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`), `input`, `textarea`, `label`, `switch`, `button`. `AppHeader` from `~/components/layout/app-header` (props `user`, `appSettings`, `menus`; already renders `<FlashMessages />` — do not add a second). `toast` from `sonner`. `useForm`, `router`, `Head` from `@inertiajs/react` (v2.3: `router.replace({ url, preserveState, preserveScroll })` is a client-side visit, no server request; `form.setDefaults()` exists).

`Input` caveat (`inertia/components/ui/input.tsx` ~66-95, 125-134): do NOT use its `error` / `helperText` props (they create `${id}-helper` and hide help on error). Render help and error paragraphs manually and pass `aria-invalid` / `aria-describedby` explicitly (they override because `{...props}` spreads last).

<decisions_applied>
- **Shell** (UI-SPEC "Page structure"): `<Head title="Réglages de la plateforme" />`, `<AppHeader user={auth.user} appSettings={appSettings} menus={menus} />`, then `<main id="main-content" className="max-w-4xl mx-auto px-4 sm:px-6 lg:px-8 py-8">`, header block `mb-8` with h1 « Réglages de la plateforme » (`text-3xl font-bold`) and intro « Modifiez l'apparence, la page d'accueil, l'accès et les coordonnées de la plateforme. Chaque onglet s'enregistre séparément. » (`text-muted-foreground mt-1`).
- **Tabs (D-01):** controlled `Tabs value={activeTab} onValueChange={setTab}`; `TabsList className="mb-6 flex-wrap h-auto gap-1" aria-label="Sections des réglages"`; triggers with icon `h-4 w-4` + label, `className="gap-2"`: `appearance` « Apparence » `Palette`, `home` « Page d'accueil » `House`, `access` « Accès » `KeyRound`, `contact` « Contact et support » `LifeBuoy`. Card titles/descriptions from the UI-SPEC Tabs table.
- **Active tab persistence (Claude's discretion, UI-SPEC Interaction 2):** initial state from the `activeTab` prop; `setTab(v)` updates state and calls `router.replace({ url: '/admin/settings?tab=' + v, preserveState: true, preserveScroll: true })` so the URL (and therefore the Referer used by VineJS's redirect-back) carries the tab; every submit uses `preserveState: 'errors', preserveScroll: true` (Inertia v2 `PreserveStateOption = boolean | 'errors' | fn`): on a validation error the component state (tab, input) is kept; on success the page remounts from the `?tab=` redirect, so the forms re-initialise from fresh props and `FlashMessages` (which only fires when the flash string changes) announces the toast again. `preserveState: true` on submit is forbidden: a second identical « Réglages enregistrés. » would never toast. Trade-off (record in the SUMMARY): unsaved edits in other tabs are dropped after a successful save; the UI-SPEC only promises they survive a tab switch. If `router.replace` misbehaves at runtime, fallback `router.get('/admin/settings', { tab: v }, { preserveState: true, preserveScroll: true, replace: true })`; record which one shipped.
- **Four forms (UI-SPEC Interaction 1):** four `useForm` hooks declared at page level (not inside `TabsContent`, which Radix unmounts), initialised from `settings` with `?? ''` for nullable strings and the four social keys. Each `TabsContent` holds `<form noValidate onSubmit=...>` → `Card` (`CardContent className="space-y-6"`) → footer row `flex justify-end mt-6` with one submit `Button`. Submit labels: « Enregistrer l'apparence », « Enregistrer la page d'accueil », « Enregistrer les règles d'accès », « Enregistrer les coordonnées »; while `processing`: `disabled`, `aria-busy="true"`, label « Enregistrement… ».
- **Submit:** `form.put('/admin/settings/' + tab, { preserveState: 'errors', preserveScroll: true, onError })` (the remount on success re-initialises the forms). `onError(errors)`: `toast.error('Certains champs sont invalides. Corrigez-les puis enregistrez à nouveau.')` and focus the first invalid field of that tab (`document.getElementById(idFor(firstKey))?.focus()`). Never clear the user's input. Success toasts come from the server flash through the existing `FlashMessages`.
- **Field markup (UI-SPEC Keyboard and screen reader):** a small local component (in the same file) renders `space-y-2` → `<Label htmlFor={id}>` (+ « (obligatoire) » in `text-muted-foreground` for `appName`, `primaryColor`, `heroTitle`, which also get `required aria-required="true"`) → control → `<p id={id + '-help'} className="text-sm text-muted-foreground">` (when help exists) → `<p id={id + '-error'} className="text-sm text-destructive">` (when error). The control gets `aria-invalid={!!error}` and `aria-describedby` = the existing help and error ids joined by a space. Ids: the field name (`appName`, …); social fields use `social-facebook`, `social-twitter`, `social-linkedin`, `social-github`; `idFor('socialLinks.facebook') === 'social-facebook'`. `maxLength` on each input equals the validator max (appName 100, URLs 255, heroTitle 150, heroSubtitle 300, announcementText 280, contactEmail 254, primaryColor 7).
- **Apparence (D-04):** `appName` Input; `appLogoUrl` Input `type="text"` placeholder `/uploads/logo.png`; `appFaviconUrl` Input `type="text"` placeholder `/favicon.ico`; `primaryColor` = `Input type="color"` (`w-12 h-9 p-1`, `aria-label="Choisir la couleur principale"`) + `Input type="text"` (`w-32 font-mono`, carries the `Label htmlFor`) bound to the same value. Logo preview when `appLogoUrl` is non-empty: `<img className="h-8" alt="Aperçu du logo">`, on `onError` hidden and replaced by `text-sm text-muted-foreground` « Image introuvable à cette adresse. » (reset when the URL changes). Help texts verbatim from the UI-SPEC Apparence table (incl. the CSP sentence for the logo, D-15).
- **Page d'accueil (D-05, D-09):** `heroTitle` Input; `heroSubtitle` Textarea `rows={3}`; `heroImageUrl` Input `type="text"`; `announcementText` Textarea `rows={2}`. Counters under `heroSubtitle` and `announcementText`: « {n} / 300 caractères » and « {n} / 280 caractères » (`text-xs text-muted-foreground`, not live). Help texts verbatim from the UI-SPEC.
- **Accès (D-06):** `Switch id="allowRegistration"` + `Label htmlFor` to its right (`flex items-center gap-2`), `aria-describedby="allowRegistration-help"`, help text verbatim from the UI-SPEC. No confirmation dialog.
- **Contact et support (D-07):** `contactEmail` `type="email"`; `supportUrl` `type="url"`; shared help line above the social grid « Réseaux sociaux : adresse complète commençant par https://. Laissez vide pour masquer l'icône. »; grid `grid grid-cols-1 md:grid-cols-2 gap-4` with Facebook, « X (Twitter) », LinkedIn, GitHub inputs `type="url"` and the UI-SPEC placeholders.
