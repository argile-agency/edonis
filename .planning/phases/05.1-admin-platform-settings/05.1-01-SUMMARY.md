# Phase 05.1 Plan 01: Settings data and validation foundation Summary

This plan adds a reversible `announcement_text` column and an `AppSetting` singleton helper. It also fixes boolean and JSON column handling, makes the seeder idempotent so admin edits survive `db:seed`, adds the admin menu item, and adds four per-tab VineJS validators with French messages and safe URL rules (http(s) only, and same-host for images).

## What was built

- **Migration** `1793600000000_add_announcement_text_to_app_settings_table.ts`: `string('announcement_text', 300).nullable()`, `down()` drops it. Tested on SQLite: migrate, seed (1 active row with the demo announcement), rollback (column gone). `schema_helpers.ts` was not needed because this is a plain string column, not JSON.
- **Model** `app/models/app_setting.ts`:
  - New `announcementText` field.
  - `socialLinks` now uses `jsonColumnConfig`, so `null` is stored as SQL NULL instead of the string `"null"`.
  - `Boolean(value)` consume on `showPublicCourses`, `allowRegistration`, `showStats` and `isActive`.
  - New `static readonly DEFAULTS` and `static async getOrCreateActive(client?)`, plus the D-14 single-instance comment.
  - `getActiveSettings()` is unchanged.
- **Seeders**: `app_setting_seeder.ts` uses `firstOrCreate({ isActive: true }, { ...DEFAULTS, welcomeMessage, contactEmail: 'contact@edonis.org', announcementText: demo, socialLinks: null })`. `menu_seeder.ts` adds the user-menu item « Réglages de la plateforme » (`/admin/settings`, `SlidersHorizontal`, order 4, visibility admin).
- **Validators** `app/validators/app_setting.ts`. Exports consumed by 05.1-05:
  - `SETTINGS_TABS` and `SettingsTab`.
  - `appSettingValidators` (`appearance`, `home`, `access`, `contact`), each compiled with `vine.withMetaData<{ appHost: string }>()` and the French `SimpleMessagesProvider`.
  - `IMAGE_URL_MESSAGE`, `LINK_URL_MESSAGE` and `COLOR_MESSAGE`.
  - The controller must call `validate(data, { meta: { appHost: request.host() ?? '' } })`.

## Deviations from Plan

- Task 2 was split into a test commit and a feat commit, following the executor's TDD protocol. The plan named a single commit.
- The functional test deletes `app_settings` rows inside the global transaction, so it starts from an empty table whatever the test DB contains. Everything is rolled back after each test.
- The seeder comment reads "Create-only: never overwrite an admin's edits..." instead of "firstOrCreate: ...". The comment the plan mandated conflicted with its own acceptance check (`grep -c firstOrCreate` must be 1).
- The validator docblock no longer names excluded columns, so that the acceptance grep for excluded fields returns 0.
- The 281-character announcement test now checks the exact French maxLength message (605aa60).
