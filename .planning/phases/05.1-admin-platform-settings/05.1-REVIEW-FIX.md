## Fixed Issues

### WR-01 / gap 1 (SETTINGS-03, D-11): whitespace-only app name and hero title

**Files modified:** `app/validators/app_setting.ts`, `tests/unit/app_setting_validator.spec.ts`, `tests/functional/app_settings.spec.ts`
**Commit:** 0240486
**Applied fix:**
- `appName` and `heroTitle` now use `trim().minLength(1)`.
- The `minLength` message is « Ce champ est obligatoire. », the same as `required`.
- No other text field is required. `primaryColor` is the only other required field, and its regex already rejects whitespace.

**Tests:**
- Unit: `'   '` is refused for `appName` and for `heroTitle`, with the French message.
- Functional: two new `INVALID_CASES` entries (PUT `/admin/settings/appearance` and `/home` with `"   "`). Each checks the field error, that the row is unchanged, and that no audit row was written.

### Gap 2 (SETTINGS-06) / IN-04: header logo and favicon URL guard

**Files modified:** `inertia/components/layout/app-header.tsx`, `resources/views/partials/favicon.edge`, `start/view.ts` (new), `adonisrc.ts`, `tests/functional/favicon_partial.spec.ts`
**Commit:** f803f8f
**Applied fix:**
- **Logo.** The logo is now rendered only when `isSafeImageSrc(settings.appLogoUrl)` passes. Otherwise the header falls back to the `GraduationCap` icon.
- **Favicon.** `start/view.ts` (a new preload) registers `isSafeImageSrc` from `inertia/lib/safe_url.ts` as an Edge global. The favicon partial calls it, so the server applies exactly the same image rule as the React side, with no copy of the rule.

**Tests:** `favicon_partial.spec.ts` has a new dataset: `javascript:alert(1)`, `//evil.example/x.png` and `/\evil.example/x.png` each render no `rel="icon"`. The existing positive case and the escaping case still pass, which also shows the global is registered.

### WR-02: support link rendered through Inertia `<Link>`

**Files modified:** `inertia/pages/home.tsx`
**Commit:** 6801823
**Applied fix:**
- « Aide et support » is now one plain `<a href>`. It gets `target="_blank" rel="noopener noreferrer"` only for http(s) URLs.
- The `isSafeLink` guard is unchanged.

**Other links checked:**
- The social links were already plain anchors.
- The footer and header menu items (`menus.footer` / `menus.header`) still use `<Link>`. They are not edited on the settings page, and every seeded URL is an Inertia route (`/about`, `/contact`, `/privacy`, `/`, `/courses`). They were left as they are.

**Tests:** no automated test, because the home page has no browser spec for this. A manual or browser check is needed with `supportUrl = /offline.html`.

### WR-03: comment on unsaved edits across tabs (comment only)

**Files modified:** `inertia/pages/admin/settings.tsx`
**Commit:** 3cb102b
**Applied fix:** Two comments were corrected to describe the accepted behaviour:
- Unsaved edits survive a tab switch.
- A successful save of any tab remounts the page, so all four forms re-initialise from server props and unsaved edits in the other tabs are lost.

Behaviour is unchanged.
