<decisions_applied>
- **Why a render guard (defence in depth):** production already holds a settings row whose `contactEmail`, `supportUrl`, `socialLinks`, `heroImageUrl` were never rendered and never passed the new validator (05.1-01). They become public the moment this plan ships. `inertia/lib/safe_url.ts` (pure, SSR-safe, no `window`):
  - `isSafeLink(url: string | null | undefined): url is string` → true for `http://`/`https://` absolute URLs (`new URL()` protocol check, in a try) or a root-relative path matching `^/(?![/\\])[^\s\u0000-\u001f\u007f]*$`
  - `isSafeImageSrc(url)` → same accepted set (CSP `imgSrc 'self'` is the backstop for foreign hosts; same-origin cannot be checked during SSR)
  - `isExternalUrl(url)` → true when absolute `http(s)://`
- **D-09 banner** (UI-SPEC "Announcement banner"): replaces the hard-coded block (home.tsx ~136-146). Rendered when `settings.announcementText?.trim()`; wrapper `<div role="region" aria-label="Annonce" className="border-b bg-primary/10">`, `<p className="container mx-auto px-4 py-2 text-center text-sm">`. Plain text only, no `dangerouslySetInnerHTML`: if `contactEmail` is non-empty and occurs in the text, split on its first occurrence and render that part as `<a href={'mailto:' + contactEmail} className="font-medium underline underline-offset-4">`, the rest as text nodes. Shown to every visitor of `/`, logged in or not.
- **Hero** (`PublicHomePage`): type its `settings` prop with the page's `AppSettings` interface (drop `any`). « Commencer maintenant » `Link` rendered only when `registrationOpen` (computed in `Home` as `const registrationOpen = !appSettings || Boolean(appSettings.allowRegistration)` and passed to `PublicHomePage` as a prop; SQLite and MySQL/MariaDB send `0`/`1` until 05.1-01's model `consume` lands, so never compare with `!== false`) (« Explorer les cours » stays, centred). When `isSafeImageSrc(settings.heroImageUrl)`: `<img src alt="" className="mx-auto mt-12 w-full max-w-4xl rounded-lg border object-cover max-h-96" loading="eager" />` after the buttons div, inside the hero `<section>` (decorative, `alt=""`).
- **Footer** (UI-SPEC "Footer"): order menu links · contact group · copyright. Contact group `flex items-center gap-4`, hidden entirely when nothing to show:
  - `contactEmail` → `Mail` icon (`h-4 w-4`, `aria-hidden="true"`) + `<a href={'mailto:' + email}>` showing the address, `text-sm text-muted-foreground hover:text-foreground`
  - `supportUrl` when `isSafeLink` → « Aide et support »: external → `<a target="_blank" rel="noopener noreferrer">`, root-relative → Inertia `Link`
  - social, order facebook, twitter, linkedin, github, only values passing `isSafeLink` and starting with `http` (empty strings and nulls skipped): icons `Facebook`, `Twitter`, `Linkedin`, `Github` (lucide, `h-5 w-5`, `aria-hidden`), link `className` includes `p-2 -m-2`, `aria-label` « {appName} sur Facebook » / « {appName} sur X » / « {appName} sur LinkedIn » / « {appName} sur GitHub », `target="_blank" rel="noopener noreferrer"`
- **AppSettings interface (home.tsx)**: add `announcementText: string | null`, `heroImageUrl: string | null`, `contactEmail: string | null`, `supportUrl: string | null`, `socialLinks: Record<string, string | null> | null` (all optional-tolerant); the null fallback object gets `allowRegistration: true` and nulls.
- **Header** (`app-header.tsx`): `AppSettings` interface gains `allowRegistration?: boolean`; « Inscription » button (~line 267-269) wrapped in `(!appSettings || Boolean(appSettings.allowRegistration)) &&` (null settings → shown, current fallback; `0`/`1` handled). Admin item in the dropdown settings group, right after « Mon compte », same `DropdownMenuItem asChild` + `Link` markup, `href="/admin/settings"`, icon `SlidersHorizontal` (add to the lucide import), label « Réglages de la plateforme », rendered only when `user.roles.some((r) => r.slug === 'admin')` (same test as `home.tsx`; check:debt only scans `app/controllers`).
- **Favicon** in a partial `resources/views/partials/favicon.edge`: `@if(page.props.appSettings?.appFaviconUrl)` → `<link rel="icon" href="{{ page.props.appSettings.appFaviconUrl }}" />` `@end`; `inertia_layout.edge` includes it with `@include('partials/favicon')` before `@inertiaHead()` (includes share the template state, so `page` is in scope). Double-curly escaping only, never triple. Why a partial: `bun run build` does not compile Edge templates and a full-page GET in functional tests needs a built Vite manifest (`grades.spec.ts` comment), so the partial is what a test can render.
- **Favicon test** `tests/functional/favicon_partial.spec.ts` (no DB, no HTTP): `import edge from 'edge.js'` (the app instance, views mounted by the Edge provider at boot); `await edge.render('partials/favicon', { page: { props: { appSettings: { appFaviconUrl: '/icons/icon-192.png' } } } })` contains `<link rel="icon" href="/icons/icon-192.png" />`; with `appFaviconUrl: null` and with `appSettings: null` the output has no `rel="icon"`; with `appFaviconUrl: '/x"><script>alert(1)</script>'` the output contains `&quot;` and no `<script>`. A new favicon shows after a full reload (Edge head), recorded for the walkthrough.
- **Unchanged:** app name, logo and primary colour rendering in the header; hero title/subtitle rendering (D-08).
