### `app/controllers/app_settings_controller.ts` (controller, request-response)

**Imports** (copy the shape of `users_controller.ts` / `files_controller.ts:1-2`):
```typescript
import type { HttpContext } from '@adonisjs/core/http'

import AppSetting from '#models/app_setting'
import AuditService from '#services/audit_service'

```

**Render shell** (`audit_logs_controller.ts:52-57`):
```typescript
return inertia.render('admin/audit-logs', { logs: logs.serialize(), filters: {...}, ... })
```
Shared props `auth`, `appSettings`, `menus` come from `config/inertia.ts` automatically. The page receives them as props (`audit-logs.tsx:65-67`, `129`).

**Controller-level authorization (D-12).** There is no controller in the repo that re-checks admin inline. Combine these two:
- `app/models/user.ts:153-158`: `await user.hasRole('admin')` (loads roles if needed)
- `app/controllers/files_controller.ts:42-46`: throw so the exception handler renders the 403
```typescript
// Thrown so the exception handler renders the 403 page for browsers
throw new Exception('You do not have access to this file', {
  status: 403,
  code: 'E_FILE_ACCESS_DENIED',
})
```
**Important:** `app/middleware/role_middleware.ts:28-31` returns `response.forbidden({ message })` (a JSON body). Non-admins are stopped there first, so on this route they get a **JSON 403, not the `errors/forbidden` Inertia page**. The UI-SPEC's "403 (existing error page)" therefore does not hold for middleware-gated routes. Tests must assert the status only. Do not use `assertInertiaComponent('errors/forbidden')`.

**Fresh-DB singleton (D-14).** Mirror the seeder's key (`app_setting_seeder.ts:7-8`, `updateOrCreate({ isActive: true }, …)`):
```typescript
// Single-instance in v1: app_settings is an is_active singleton without tenant_id (D-14)
const settings = await AppSetting.firstOrCreate({ isActive: true }, { appName: 'Edonis LMS', primaryColor: '#5046E5', allowRegistration: true, /* … */ })
```
Use the same call in `show` and in `update`. It never inserts a second active row.

**Update + audit diff (D-13).** The analog `users_controller.ts:181-251` logs the full `serialize()` before and after:
```typescript
const oldValues = user.serialize()
const data = await request.validateUsing(updateUserValidator)
user.merge({ ... })
await user.save()
await AuditService.logFromContext(ctx, {
  action: 'admin.user.update',
  resourceType: 'User',
  resourceId: user.id,
  oldValues,
  newValues: user.serialize(),
})
session.flash('success', 'Utilisateur mis à jour avec succès')
return response.redirect().toRoute('users.index')
```
D-13 wants the **changed keys only**. After `settings.merge(data)`, read `settings.$dirty` and `settings.$original[key]` before `save()`, and build `oldValues`/`newValues` from those keys. Verify that `$dirty` flags `socialLinks` when only one nested key changes (it is an object, so Lucid compares by value or reference depending on version). If it does not, compare `JSON.stringify` manually. Empty diff: flash « Aucune modification à enregistrer. », no audit row (UI-SPEC Q10).

**Save + audit in one transaction** (`course_bulk_actions_controller.ts:620-634`):
```typescript
outcome = await db.transaction(async (trx) => {
  // ...
  // In the transaction: a failed audit write rolls the change back (committed ⇔ audited)
  await AuditService.logFromContext(ctx, { action: ..., resourceType: 'Course', resourceId: course.id, metadata: {...} }, trx)
})
```
Use `settings.useTransaction(trx)` (pattern at `categories_controller.ts:144-160`). Suggested action name: `admin.settings.update`, `resourceType: 'AppSetting'`.

**Redirect with the active tab** (UI-SPEC Interaction 2): `response.redirect().toPath('/admin/settings?tab=' + tab)` or `redirect().back()`. On validation failure, VineJS redirects back with `inputErrorsBag` and no flash (`categories.spec.ts:165`).

### `app/validators/app_setting.ts` (validator)

**Analog:** `app/validators/profile_validator.ts:9-28`
```typescript
import vine from '@vinejs/vine'

export const updateProfileValidator = vine.compile(
  vine.object({
    firstName: vine.string().trim().maxLength(255).optional().nullable(),
    email: vine.string().trim().email().normalizeEmail(),
    bio: vine.string().trim().maxLength(1000).optional().nullable(),
    ...
  })
)
```
- Max lengths come from the UI-SPEC tables: appName 100, URLs 255, heroTitle 150, heroSubtitle 300, announcementText 280, contactEmail 254, primaryColor regex `/^#[0-9a-f]{6}$/i`, stored uppercase.
- Existing `.url()` calls (`user_validator.ts:12`, `course_content.ts:54`) use default protocols. That is **not enough**: links need `http(s)` only, image fields need root-relative or same-origin, and `javascript:`/`data:` must be refused. Use explicit `.regex()` (pattern at `course_admin.ts:17`) or `.url({ protocols: ['http', 'https'], require_protocol: true })`, plus a root-relative branch for supportUrl and the image fields.
- Empty optional → `null`: `.optional().nullable()` plus `.transform((v) => v || null)`, or normalise in the controller.
- `socialLinks`: `vine.object({ facebook, twitter, linkedin, github })`. VineJS drops unknown keys by default (no `.allowUnknownProperties()`).
- One validator per tab, or one with a `tab` discriminator (Claude's discretion).
- **French messages: no analog** (see No Analog).

## Shared Patterns

### Audit logging
**Source:** `app/services/audit_service.ts:45-59` (`logFromContext(ctx, options, client?)`)
**Apply to:** the settings save. Pass `trx` when saving inside a transaction (`course_bulk_actions_controller.ts:625-634`).

### Flash + redirect
**Source:** `social_auth_controller.ts:41-43`, `users_controller.ts:249-250`
**Apply to:** settings save (success / no-change), register guards, OAuth guard. The message reaches the user through `FlashMessages` (`components/flash-toaster.tsx`, sonner + `aria-live`).

### JSON columns
**Source:** `app/helpers/json_column.ts` (`jsonColumnConfig`)
**Apply to:** `AppSetting.socialLinks`.

### Shared props on the client
**Source:** `config/inertia.ts:36-45`. Pages read them either as props (`audit-logs.tsx:65-67`) or through `usePage` (`terms-consent-banner.tsx:6`).
**Apply to:** home, app-header, login, about, settings page.

### Admin route guard
**Source:** `start/routes.ts:200-204`, `middleware.auth()` + `middleware.role({ roles: ['admin'] })`, plus a controller re-check (`user.hasRole('admin')` + `throw new Exception(…, { status: 403 })`).
