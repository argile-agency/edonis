## Interaction contract

1. **Four independent forms.** Declare four `useForm` hooks at page level (not inside `TabsContent`, which Radix unmounts), so unsaved edits survive a tab switch. Each form submits only its own fields; nothing in another tab is touched. No "unsaved changes" dialog in v1.
2. **Active tab survives the save round-trip**, success or failure. Controlled `Tabs`; the planner picks the mechanism (`?tab=` query read on load and kept on redirect, or `preserveState`). Default tab: `appearance`.
3. **Submit:** button label per tab — Apparence « Enregistrer l'apparence », Page d'accueil « Enregistrer la page d'accueil », Accès « Enregistrer les règles d'accès », Contact et support « Enregistrer les coordonnées »; while `processing`: disabled, label « Enregistrement… », `aria-busy="true"`. Enter in a single-line input submits that tab's form.
4. **Success:** redirect back, flash `success` → toast « Réglages enregistrés. » (announced through the existing `aria-live` region). Form `defaults` reset to the saved values. Header/footer reflect the change on the next render (shared prop `appSettings`).
5. **Validation failure:** nothing persisted (D-11). Per field: error `<p id="{field}-error" class="text-sm text-destructive">` placed right under the control; the control gets `aria-invalid="true"` and `aria-describedby="{field}-help {field}-error"` (help id always present when help exists). Focus moves to the first invalid field of the submitted tab. VineJS failures redirect back with field errors and no flash, so the error toast is client-side: `useForm` `onError: () => toast.error('Certains champs sont invalides. Corrigez-les puis enregistrez à nouveau.')` (sonner, already mounted). Do not clear the user's input.
6. **Unchanged save:** allowed; when no key changed, flash `success` « Aucune modification à enregistrer. » (audit row for an empty diff: planner's call, see Open questions 10).
7. **Server error (500 / network):** existing error page / Inertia default; no custom UI.

### Keyboard and screen reader (D-03)

- Tabs: Radix default — Tab moves into the list, Left/Right arrows switch tabs, Home/End jump; activation automatic. `TabsList` has `aria-label="Sections des réglages"`.
- Every control has a visible `<Label htmlFor>`; ids are unique across the four tabs (prefix not needed: field names are unique).
- Help text: `<p id="{field}-help" class="text-sm text-muted-foreground">`, referenced by `aria-describedby`.
- Required fields: `required` + `aria-required="true"`, and « (obligatoire) » appended to the label text in `text-muted-foreground` (no asterisk-only marker).
- Focus ring: existing `focus-visible:ring-2 ring-ring` on all primitives; do not override.
- The skip link « Aller au contenu principal » in `AppHeader` targets `#main-content`: the page's `<main>` must carry that id.
- axe-core test (critical/serious) on `/admin/settings`, logged in as admin, on the default tab and after switching to each of the other three tabs.

### Footer (D-08) — `home.tsx` footer

Current: `flex flex-col md:flex-row justify-between items-center gap-4` with menu links left and copyright right. Add a middle group (order: menu links · contact group · copyright), `flex items-center gap-4`:

### Favicon (D-08) — `resources/views/inertia_layout.edge`

Because it lives in the Edge `<head>`, a new favicon appears after a full page reload, not after the Inertia redirect; the acceptance check must reload.

## Open questions / defaults chosen

Defaults the planner may follow; none reopens a locked decision.

1. **Admin menu entry visible only via header code** (finding above): seeder item per D-02 **plus** a hard-coded, admin-only item in `app-header.tsx`. Alternative (larger): render `menus.userMenu` in the dropdown — not chosen, it would also surface the stale `/profile`, `/settings`, `/admin` seeder URLs.
2. **Active-tab persistence mechanism**: `?tab=` vs `preserveState` — planner's choice; the behaviour is the contract.
3. **Hero CTA when registration is off**: hidden (not redirected to `/login`), « Explorer les cours » remains.
4. **OAuth sign-up bypass**: `social_auth_controller.ts` creates a user on first OAuth callback (`User.create`, line ~71). The planner must decide whether `allowRegistration = false` also blocks OAuth account creation (recommended: yes, same flash message on `/login`; existing linked users still log in). Not a UI decision, flagged because it decides whether the switch's help text is true.
5. **Required fields**: only `appName`, `primaryColor`, `heroTitle`. Everything else optional, empty → `null`.
6. **Support URL** accepts `http(s)://` and root-relative paths; social links `http(s)://` only.
7. **Announcement max length** 280 (UI + validator); the new column's type is the planner's call (`string(300)` or `text`).
8. **Logo preview** only (no favicon/hero preview, no live theme preview — out of scope per brief).
9. **Footer changes apply to `home.tsx` only** (the only page with this footer today); no shared footer component is extracted.
10. **No-change save** shows « Aucune modification à enregistrer. »; whether an audit row is written for an empty diff is the planner's call (recommended: no row).
