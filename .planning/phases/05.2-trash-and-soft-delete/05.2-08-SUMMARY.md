# Phase 05.2 Plan 08: Course trash page Summary

`/courses/:id/trash` is now a page. It shows a table of trash roots and a days-left badge that turns into a warning at 3 days or fewer. Each row restores in one click, and a content whose section is also trashed opens the D-05 dialog. Owners and admins also get the « Supprimer définitivement » and « Vider la corbeille » confirmations with the learner count. The course page « Contenu » tab links to it, and an axe-checked browser spec covers it.

## What was built

- **Page (S1).** It has every column of the UI-SPEC, with its responsive classes, plus the mobile fold « {Type} · {date} ». Labels come from the copy contract: « Racine du cours », « (dans la corbeille) » and « Utilisateur supprimé » (null `deletedBy`). The server sends « Utilisateur sans nom » as is. Dates sit in `<time dateTime>` in the audit-logs format without seconds, with an sr-only caption and an sr-only Actions header. Each row button has an aria-label specific to its title.
- **Badge (D-15).** It uses `Badge variant="outline"`. At 3 days or fewer it adds `bg-warning/10 border-warning` and an `AlertTriangle` icon, and at 0 or fewer it reads « Aujourd'hui ». The page never uses `text-warning` or `soft-warning`.
- **R1 (D-05)** is a `Dialog` with two steps:
  - Step 1: « Restaurer aussi la section « S » » posts `withSection: true`.
  - Step 2: `MoveTargetList idBase="trash-{id}"` posts `moduleId`, and « Retour aux options » goes back.
  - Focus moves between the steps.
- **P1 and P2** are `AlertDialog`s with `LearnerImpact variant="permanent"`, fed by `delete-impact` with the row's `contentIds` (P2 uses every row's). The line is skipped when there are no ids. The confirm buttons keep the destructive styling.
- **Requests.** `router.post` with `preserveScroll`. A single `busy` key disables every action and sets `aria-busy` on the clicked button. After a visit, focus goes to the same row if it stayed (error flash), else the next surviving row's « Restaurer », else the previous one, else `#trash-heading`. Confirmed dialogs prevent the default close focus.
- **Permissions.** When `canPurge` is false, the purge buttons are not rendered and the collaborator note shows. The server stays the control (T-05.2-32 is transferred to 05.2-09).
- **show.tsx (S3).** A « Corbeille » outline `size="sm"` link sits first in the editors-only button row.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Payload type for `router.post`**
- **Found during:** Task 1 (inertia tsconfig check)
- **Issue:** `Record<string, unknown>` is not assignable to Inertia's `RequestPayload`.
- **Fix:** The helper now takes `Record<string, string | number | boolean | null>`.
- **Commit:** a143fa6

**2. [Rule 1 - Bug] Focus could land before the new rows were committed**
- **Issue:** Inertia calls `onSuccess` before React commits the new page, so a single `requestAnimationFrame` could focus a button that is about to disappear.
- **Fix:** Focus is now applied after two frames.
- **Commit:** d289940
