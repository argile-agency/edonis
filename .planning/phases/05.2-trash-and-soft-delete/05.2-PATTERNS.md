## Pattern Assignments

### `database/migrations/1793700000000_add_trash_columns_to_course_structure.ts` (migration)

**Analog:** `database/migrations/1793500000000_add_copied_from_id_to_course_structure.ts` (whole file, 46 lines)

Copy the `disableTransactions` flag with its comment and the two-table `alterTable` shape. The comment must change: here the danger is `down()` (`dropColumn` rebuilds the table on SQLite), not the FK. RESEARCH recommends **no FK** on `deleted_by_id`.
```typescript
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  // On SQLite knex adds a foreign key by rebuilding the table (copy, drop, rename) with
  // PRAGMA foreign_keys off, but SQLite ignores that pragma inside a transaction: dropping
  // the original course_modules would cascade-delete contents, sub-sections and progress.
  static disableTransactions = true

  async up() {
    this.schema.alterTable('course_modules', (t) => {
      t.integer('copied_from_id')
        .unsigned()
        .nullable()
        .references('id')
        .inTable('course_modules')
        .onDelete('SET NULL')
      t.index(['copied_from_id'])
    })
    this.schema.alterTable('course_contents', (t) => { /* same */ })
  }

  async down() {
    // Foreign key first: MySQL refuses to drop an index a foreign key relies on
    this.schema.alterTable('course_contents', (t) => {
      t.dropForeign(['copied_from_id'])
      t.dropIndex(['copied_from_id'])
      t.dropColumn('copied_from_id')
    })
    this.schema.alterTable('course_modules', (t) => { /* same */ })
  }
}
```
Target columns (RESEARCH § Migration design): `t.timestamp('deleted_at').nullable()`, `t.string('deleted_batch', 36).nullable()`, `t.integer('deleted_by_id').unsigned().nullable()`. Indexes: `['course_id','deleted_at']` on modules, `['module_id','deleted_at']` on contents, `['deleted_batch']` on both. `down()` order is `dropIndex` ×2, then `dropColumn` ×3 per table. Contents go first, as in the analog.

## Shared Patterns

### Authorization
**Source:** `app/policies/course_policy.ts:65-78`; call shape `course_bulk_actions_controller.ts:608-609`.
**Apply to:** every trash route (`edit` for index/restore/restore-batch, `emptyTrash` for delete/empty). Never inline role or owner checks in controllers (`check:debt`).

### Course lock + transaction + audit-in-trx
**Source:** `course_bulk_actions_controller.ts:618-641` (BulkRefusal thrown inside and caught outside, because PostgreSQL aborts the trx).
**Apply to:** trash (single + bulk), restore, restoreBatch, forceDelete, purge per course.

### Audit
**Source:** `AuditService.logFromContext(ctx, {action, resourceType, resourceId, metadata}, trx)` (`audit_service.ts:45-58`). CLI: `AuditService.log({ userId: null, ... }, trx)` (`audit_service.ts:21`).
**Actions:** keep `course.module.delete` / `course.content.delete` / `course.bulk.delete` (+`batch`); new `course.trash.restore`, `course.trash.delete`, `course.trash.empty`, `course.trash.purge`. Metadata holds ids only.

### Cross-engine read-back
- Booleans: `Boolean(x)` (`builder_props.ts:59-60`).
- Counts: `Number(...)` (`course_bulk_actions_controller.ts:593`).
- Raw datetimes: `Date` on pg/mysql2, string on SQLite. Parse both in one helper.
- Writes and comparisons: `toFormat(trx.dialect.dateTimeFormat)` (`course_bulk_actions_controller.ts:214`).

### Flash + toasts
- Server flash → toast is automatic: `inertia/components/flash-toaster.tsx:21-25` (`toast.success(flash.success)` / `toast.error(flash.error)`). The trash page only sets `session.flash`.
- Client toasts: `import { toast } from 'sonner'` (`settings.tsx:3`; `builder.tsx` does not import it yet). The Toaster is mounted at `inertia/app/app.tsx:33`.

### Validation
**Source:** `request.validateUsing(validator)` with a VineJS `vine.compile` schema (`course_bulk.ts`); settings tab validators use `withMetaData` + `messagesProvider` (`app_setting.ts:50-62`).
