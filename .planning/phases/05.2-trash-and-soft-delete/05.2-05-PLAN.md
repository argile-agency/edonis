- `DELETE /modules/:moduleId` and `DELETE /contents/:contentId` (existing routes, existing `CoursePolicy` edit check): JSON callers (`Accept: application/json`) get 200 `{ item: { id: number }, batch: string }`. - `POST /courses/:id/builder/bulk/delete` (existing body `{ items }`): 200 `{ sections, contents, affected, deleted, batch }` where `deleted` = every section and content id that left the live tree (selected rows and all their descendants) and `batch` = the one batch id of the operation. - Builder page props gain `trash: { count: number; retentionDays: number }`: `count` = number of trash-list roots of the course (a batch root is a trashed row whose parent is not trashed in the same batch), `retentionDays` = `AppSetting.trashRetentionDays`.
<!-- END DELETE CONTRACT -->

<!-- RESTORE-BATCH CONTRACT — identical copy in 05.2-05 (consumer) and 05.2-09 (producer). -->
- `POST /courses/:id/trash/restore-batch`, JSON body `{ batch: string (uuid) }`, `CoursePolicy` edit. 200 = bulk shape `{ sections, contents, affected, deleted }` (`BulkResult` of `inertia/lib/builder_tree.ts:456`; `deleted` empty; `affected` = restored ids plus renumbered siblings) — apply with `mergeBulkResult` (restored rows arrive through its "added" branch).
- 409 `{ code: 'E_PARENT_TRASHED', section: { id, title }, message }`: a content of the batch has its section in the trash (another editor trashed it); nothing restored.
- 404 `{ code: 'E_NOT_IN_TRASH', message }`: no trashed row of this course carries the batch (already restored or purged).
<!-- END RESTORE-BATCH CONTRACT -->
