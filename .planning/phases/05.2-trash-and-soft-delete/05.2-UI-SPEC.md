## S1 — Trash page `/courses/:id/trash`

Analog: `inertia/pages/admin/audit-logs.tsx` (table in a card, `AppHeader`), and the builder header for the back link.

```
<Head title="Corbeille - {course.title}" />
<AppHeader user appSettings menus />                 ← renders FlashMessages; no second <FlashMessages />
<main id="main-content" class="container mx-auto px-4 py-8">
  header block (flex justify-between items-start gap-4 mb-8, wraps on mobile: flex-col sm:flex-row):
    left:
      <Link href="/courses/{id}/builder"> Button variant="ghost" size="sm" mb-2 :
        ArrowLeft h-4 w-4 mr-2 + "Retour à l'éditeur"
      h1 "Corbeille"  text-3xl font-bold  tabIndex={-1} id="trash-heading"  (focus target, outline-none)
      p  "{course.title}"                   text-muted-foreground mt-2
      p  retention line                     text-sm text-muted-foreground mt-1
    right (only when canPurge && rows.length > 0):
      Button variant="outline" : Trash2 h-4 w-4 mr-2 + "Vider la corbeille"
  [collaborator note, only when !canPurge && rows.length > 0]  text-sm text-muted-foreground mb-4
  <Card> <CardContent class="p-0"> <Table> ... </Table> </CardContent> </Card>
    or the empty state Card (see States)
</main>
```

Focal point: the table. The page has **no** `--primary` filled button: restoring is per row, and the destructive actions are outline buttons. This is deliberate, because no single action dominates the page.

### Table columns (D-17), in this order

| # | Header | Cell content | Classes / responsive |
|---|--------|--------------|----------------------|
| 1 | Élément | Title in `font-medium`. A section row adds a second line « avec {n} élément(s) » (`descendantCount`, `text-xs text-muted-foreground`), only when n > 0 | always visible |
| 2 | Type | Singular label: Section, Page, Vidéo, Fichier, Lien, Devoir, Quiz | `hidden md:table-cell`, `text-sm` |
| 3 | Section d'origine | Original parent title. A root section shows « Racine du cours ». A content whose section is also in the trash adds « (dans la corbeille) » in `text-muted-foreground` | `hidden lg:table-cell`, `text-sm` |
| 4 | Supprimé par | `deletedBy` full name; « Utilisateur supprimé » when null or dangling | `hidden lg:table-cell`, `text-sm` |
| 5 | Supprimé le | `dd/mm/yyyy hh:mm` (`toLocaleString('fr-FR', { day, month, year: 'numeric', hour, minute })`, the audit-logs format without seconds) inside `<time dateTime={iso}>` | `text-xs text-muted-foreground whitespace-nowrap`, `hidden sm:table-cell` |
| 6 | Suppression définitive | Days-left badge (below) | `whitespace-nowrap` |
| 7 | `<span class="sr-only">Actions</span>` | Row buttons (below) | `text-right whitespace-nowrap` |

On mobile (< 640px) only Élément, Suppression définitive and Actions remain. Type and date are folded into the Élément cell's second line as « {Type} · {date} » under `sm:hidden`, so no information is lost.

**Days-left badge (D-15).** `Badge variant="outline"` with `size` default:
- `daysLeft > 3`: « Dans {n} jours », with default outline styling (`text-foreground border-border`).
- `1 ≤ daysLeft ≤ 3`: add `className="bg-warning/10 border-warning"` (keep the outline variant's `text-foreground`, which flips with the theme; `text-warning-foreground` is near-black in dark mode, on a near-black background) and `icon={<AlertTriangle className="h-3 w-3" aria-hidden="true" />}`. Text « Dans {n} jour(s) » (« Dans 1 jour », « Dans 2 jours »).
- `daysLeft ≤ 0` (expired but not yet purged; it cannot normally happen because the page purges on open): « Aujourd'hui », with the same warning styling.
- **Never** use `text-warning` or `soft-warning` for this text. Amber on near-white is about 2:1 and fails axe. The tinted background, the border and the icon carry the colour; the text stays `text-foreground`. The changed wording plus the icon means colour is not the only cue (WCAG 1.4.1).

**Row actions.** `flex justify-end gap-2`:
- « Restaurer »: `Button variant="outline" size="sm"`, `RotateCcw h-4 w-4 mr-2`, `aria-label="Restaurer « {titre} »"`.
- « Supprimer définitivement » (only when `canPurge`): `Button variant="outline" size="sm"`, `aria-label="Supprimer définitivement « {titre} »"`. **No red text**: `text-destructive` at 12-14px fails AA. This follows the precedent in `bulk-action-bar.tsx:251`. Red is reserved for the dialog's confirm button.

Sort: most recent first (`deletedAt desc, id desc`), done server-side. No pagination in v0.1 (research: shortcut comment server-side).

### Dialogs on the trash page

All use `AlertDialog`, except the D-05 destination step, which uses `Dialog` (a list, not a confirmation, as in « Déplacer vers… »).

**P1 — Permanent delete of one row** (`AlertDialog`)
- Title: « Supprimer définitivement « {titre} » »
- Description, content: « Ce contenu sera supprimé définitivement. Cette action est irréversible. »
- Description, section: « Cette section sera supprimée définitivement avec ses sous-sections et contenus, y compris ceux mis à la corbeille séparément. Cette action est irréversible. » (research § Purge: the FK cascade takes earlier-trashed children).
- `LearnerImpact variant="permanent"` loads with the row's `contentIds`. Section subject: « cette section ». Content subject: « ce contenu ». When `contentIds` is empty (a section with no contents), skip the fetch and do not render the line.
- Footer: `AlertDialogCancel` « Annuler » + `AlertDialogAction` « Supprimer définitivement ». The action uses the existing destructive styling: `bg-destructive text-destructive-foreground hover:bg-destructive/90`.

**P2 — Vider la corbeille** (`AlertDialog`)
- Title: « Vider la corbeille »
- Description: « Les {n} élément(s) de la corbeille seront supprimés définitivement, avec leurs sous-sections et contenus. Cette action est irréversible. » (n = row count; use the existing `elements()` helper wording: « 1 élément », « 3 éléments »).
- `LearnerImpact variant="permanent"` with every row's `contentIds` concatenated. Subject: « les éléments de la corbeille ».
- Footer: « Annuler » + « Vider la corbeille » (destructive styling).

**R1 — Restore a content whose section is in the trash (D-05)** (`Dialog`)

Triggered **client-side** with no round-trip: content rows carry `sectionTrashed: { id, title } | null`, and the page receives `moveTargets` (live sections only, depth rules as in `builder_tree.ts`, no root target, because a content needs a section). Clicking « Restaurer » on a row with `sectionTrashed !== null` opens R1 directly. The server's 409 `E_PARENT_TRASHED` stays as a race guard and comes back as a redirect with a flash error (below), never as raw JSON to `router.post`.

- Title: « Restaurer « {titre} » »
- Description: « Sa section « {section} » est aussi dans la corbeille. »
- Step 1 (default view), two stacked full-width buttons, `flex flex-col gap-2`:
  1. `Button` (default/primary, the only primary filled element on the page, and only while R1 is open): « Restaurer aussi la section « {section} » ». It posts `withSection: true`.
  2. `Button variant="outline"`: « Restaurer dans une autre section… ». It switches the dialog body to step 2 (same dialog, no stacking).
- Step 2: description changes to « Choisissez la section de destination. Le contenu sera placé à la fin. », then `MoveTargetList idBase="trash-{id}" targets={moveTargets}`, then a `Button variant="ghost" size="sm"` « Retour » that goes back to step 1. Choosing a target posts `moduleId`.
- When `moveTargets` is empty, `MoveTargetList` already renders « Aucune destination disponible. »; option 1 still works.
- Footer (both steps): `Button variant="outline"` « Annuler » (DialogClose).
- Restoring « aussi la section » restores the section **and its batch descendants** (D-07), so other rows may disappear too. The success flash says what came back (see Copy).

Plain rows (sections, or contents whose section is live) restore with **no** confirmation: restoring is non-destructive and reversible.

### Interaction contract (trash page)

1. **Requests.** Use Inertia `router.post` (not the builder save queue) with `preserveScroll: true`. The server answers with a redirect back + flash. While a request is in flight, disable **all** row buttons and the « Vider la corbeille » button (one `processing` state for the page, `aria-busy="true"` on the clicked button). This prevents double restores; the server's 404 `E_NOT_IN_TRASH` covers racing editors.
2. **Focus after a row disappears** (restore, permanent delete): move focus to the next row's « Restaurer » button. If it was the last row, use the previous row's. If the table is now empty, focus `#trash-heading` (h1, `tabIndex={-1}`). Dialogs: `onCloseAutoFocus` → `preventDefault()` and apply the same rule after the visit finishes (`onSuccess`). On cancel, focus returns to the trigger (Radix default).
3. **Lazy purge on open** (D-12) is invisible: no message, no spinner. Rows that expired are simply gone. A purge failure is logged server-side and the page renders normally.
4. **Permissions** (D-09/D-10): the page receives `permissions: { canPurge }`. When false, the « Supprimer définitivement » buttons and « Vider la corbeille » are **not rendered** (not disabled), and the collaborator note is shown. The server enforces this regardless.
5. **Server error (500 / network):** the existing Inertia default; no custom UI.

## S7 — Undo toast (D-18)

- Shown from the queue op's `run()` **after** the server answers (the batch id exists only then; research Pitfall 4). Never at enqueue time.
- Single: `toast(\`« ${title} » déplacé dans la corbeille.\`, { duration: 10_000, action: { label: 'Annuler', onClick: () => undo(batch) } })`. Same masculine form for sections and contents, as written in D-18.
- Bulk: `toast(\`${elements(n)} déplacé${n > 1 ? 's' : ''} dans la corbeille.\`, …)` with the same action and duration. « 1 élément déplacé… », « 3 éléments déplacés… ». n = number of selected roots.
- Neutral `toast()` (not `toast.success`): with `richColors`, the success style would compete with the action button.
- `undo` enqueues a save-queue op (POST `restore-batch`), so `SaveStatus` shows saving, then saved. On success: `toast.success('Restauration effectuée.')` and the trash count is decremented. Clicking « Annuler » dismisses the toast (sonner default).
- Undo failure:
  - 409 `E_PARENT_TRASHED` (OQ3): `toast.error('Restauration impossible : la section a été supprimée. L\'élément reste dans la corbeille.')`
  - 404 `E_NOT_IN_TRASH` (already restored or purged): `toast.error('Cet élément n\'est plus dans la corbeille.')`
  - other: the queue's existing error handling (SaveStatus retry).
- Accessibility: sonner's toaster is an `aria-live` region and the action is a real button. It is reachable with the toaster hotkey (Alt+T, sonner default) and has `closeButton`. The 10 s limit is acceptable (WCAG 2.2.1) because the trash page is an untimed path to the same outcome; the toast is a shortcut, not the only way.
- Focus after the delete: unchanged from Phase 5 (`onCloseFocusTarget` / `focusSelectAll`). The toast does **not** take focus.

**Class whitelist rule.** `app.css` hand-writes colour utilities with no Tailwind theme mapping, so only classes present in `app.css` render. Confirmed present: `bg-warning/10` (l.237), `border-warning` (l.354), `text-foreground` (l.325), `text-destructive` (l.292), `hover:bg-destructive/90` (l.272), `text-muted-foreground` (l.322). Any other colour, state or variant class (`hover:`, `data-[state]:`, `focus:` on a new token) must use arbitrary values, e.g. `hover:bg-[hsl(var(--warning)/0.2)]`, following `inertia/components/ui/switch.tsx`. Do **not** use `text-warning` or the `soft-warning` badge variant for text (amber on near-white ≈ 2:1).

## Open questions / defaults chosen

Defaults the planner may follow; none reopens a locked decision.

1. **D-05 dialog without a 409 round-trip.** The rows carry `sectionTrashed` and the page carries `moveTargets` (server-computed from the live structure), so the dialog opens client-side. Inertia would show a raw JSON 409 in its error modal. The server 409 remains a race guard (redirect + flash). Restore endpoints branch on `wantsJson` (JSON bulk shape for the builder undo, redirect for the page), per research.
2. **Depth / missing-parent fallback** (research OQ1): restore to the end of the root sections, with the fallback flash.
3. **Undo after the section was trashed meanwhile** (research OQ3): error toast; the item stays in the trash.
4. **Undo toast style:** neutral `toast()`, not `toast.success`, 10 000 ms, sonner action. Success and errors after undo use `toast.success` / `toast.error`.
5. **Trash button with 0 items:** visible, label « Corbeille » without a count.
6. **No confirmation on plain restore** (non-destructive, reversible). Permanent delete and empty always confirm.
7. **Pre-existing contrast:** white on `--destructive` (#D74242) is about 4.4:1, just under 4.5:1 for 14px medium text, on the existing confirm buttons. Kept as is (pre-existing, shared with Phase 5). If the axe run with an open dialog flags it, darken `--destructive` in `app.css` in a separate fix, not in this phase.
8. **« Corbeille » on the course page** is placed first in the Contenu tab button row, with no count (no extra prop).
9. **Mobile table:** Type and date fold into the title cell below 640px; section and author are hidden below 1024px (still available by widening; the restore flow does not need them).
10. **Assignments reappearing after purge** (research Pitfall 6): no UI text in this phase. The P1 section dialog does not mention assignments; submissions and grades are never deleted. The SUMMARY documents it.
11. **Short row CTAs:** the visible row labels stay « Restaurer » / « Supprimer définitivement » for table density; the noun is the row itself and the title-specific `aria-label` (« Restaurer « {titre} » »).
12. **Date formatting under SSR:** format with `toLocaleString('fr-FR', …)` as audit-logs does. If hydration warnings appear (server and client time zones differ), format server-side and pass the string.
