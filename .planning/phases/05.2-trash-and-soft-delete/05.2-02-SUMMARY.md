# Phase 05.2 Plan 02: Trash retention setting Summary

The admin can now set how long deleted items stay in the trash, from 1 to 365 days with a default of 30. The value is stored in `app_settings.trash_retention_days`, validated by a new `trash` VineJS tab and audited through the existing `admin.settings.update` row (`metadata.tab: 'trash'`). It is served as a number in the page props and edited in a fifth « Corbeille » tab on `/admin/settings`.

## Deviations from Plan

- **Label literal:** the acceptance check asks `settings.tsx` to contain the literal « Durée de conservation (obligatoire) ». The page follows the 05.1 `Field required` convention, which renders that exact label but stores « (obligatoire) » in the shared span. A JSX comment next to the field records the rendered label. I did not hard-code the suffix, which would have duplicated « (obligatoire) ».
- **Lint fix (Rule 3):** two new test lines used `(await x).prop`, which `@unicorn/no-await-expression-member` rejects. They now go through a local variable. This change is in the feat commit.
- **Help id literal (e93968b):** `describedBy` built `trashRetentionDays-help` from the id. It is now passed explicitly as the helper's `helpId` argument (same rendered id), following the 05.1-04 "literal ids" convention.
- **Extra coverage:** the unit "every tab drops headerHtml and isActive" loop now includes `trash`.
