# Phase 05.2 Plan 05: Builder trash UI Summary

The builder now sends any section, non-empty ones included, to the trash. The single and bulk dialogs give the retention period and the learner count over the whole subtree. A neutral 10 s « Annuler » toast restores the batch through the save queue, and the header shows « Corbeille (N) ».

## What changed

- `builder_tree.ts`: `NOT_EMPTY_MESSAGE`, `canDeleteSection`, `BULK_DELETE_BLOCKED_MESSAGE` and `bulkDeleteBlockers` are deleted. `bulkDeletedIds` feeds the delete-impact requests (single and bulk).
- `LearnerImpact`: `variant: 'trash' | 'permanent'` (default `'trash'`) and `retentionDays`, following the S8 copy. It exports `dayCount(n)` (« 1 jour » / « N jours »). The trash page (05.2-07) can reuse it with `variant="permanent"`.
- `ItemActionsMenu`: « Supprimer » is always enabled. The S4 titles, descriptions and confirm labels are « Supprimer la section » / « Supprimer le contenu ». The impact also shows for sections, but only when the subtree contains contents. `canDelete` is replaced by `hasDescendants` and `retentionDays`.
- `BulkActionBar`: the blocked branch is gone. It uses the S6 description and the confirm label « Supprimer {elements(n)} ». `elements` is now exported.
- `builder.tsx`: types `trash: { count, retentionDays }` locally. It keeps a `trashCount` state and adds:
  - `offerUndo` (neutral `toast()`, `duration: 10_000`, action « Annuler »), called from inside the single and bulk delete `run()` once the server has answered.
  - `undo(batch, roots)`, a queue op labelled « Restaurer » that posts restore-batch. It merges the result with `mergeBulkResult` (snapshot taken in `apply()`), expands restored sections and shows `toast.success('Restauration effectuée.')`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A single section delete only removed the section row**
- **Found during:** Task 1
- **Issue:** `remove()` dropped only the section row. That was fine while only empty sections could be deleted. Now that non-empty sections can be deleted, their sub-sections and contents would have stayed on screen. Focus would also have moved to the section's first child, which was being deleted with it.
- **Fix:** the optimistic step removes `bulkDeletedIds(..., [ref])`. The focus neighbour is now the next row outside the deleted subtree, or failing that the previous one.
- **Files modified:** inertia/pages/courses/builder.tsx
- **Commit:** 7718676

**2. [Rule 3 - Blocking] Name clash with the bulk bar's `days` state**
- The helper is named `dayCount` instead of `days`.

## Known Stubs / Integration notes

- Until 05.2-03 merges, the server does not send `props.trash`, so `props.trash.retentionDays` throws when the builder renders. This is expected for parallel wave 2. The plan types the prop locally on purpose.
- The undo uses `res.batch!` / `result.batch!`, relying on the contract. A server that omits `batch` would make the undo POST fail validation, which shows in the queue's error state.
