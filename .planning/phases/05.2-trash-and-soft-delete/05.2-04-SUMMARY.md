# Phase 05.2 Plan 04: Trash purge service and trash:purge command Summary

One service now physically deletes trashed sections and contents once they are older than the retention setting. It runs per course, under the course lock, in its own transaction, and writes an in-transaction `course.trash.purge` audit row. Purging a section also removes the contents under it, including ones trashed earlier in another batch. Learner progress and file pivots go with the contents through the FK cascades. Assignments are detached through `ON DELETE SET NULL`, and their submissions and grades are kept. A stored file is deleted (row, then blob after commit) only when no remaining content, live or trashed, still references it. `node ace trash:purge` drives the service for every course that has expired items.

## Notes

- **Pitfall 6 / D-08:** after a section is purged, its assignments have `module_id = NULL`. They reappear, unattached, in the gradebook, and their submissions and grades are intact.
- **Accepted race (T-05.2-18):** an upload of the same bytes can reuse a `ContentFile` row between the orphan select and delete, and its pivot insert then fails on the FK. This is marked with a `shortcut:` comment in the service.
- **Local `CHUNK = 100`:** used instead of importing `PIVOT_CHUNK`, because 05.2-03 extracts `builder_ids.ts` in parallel. It can be switched to that import after merge.
- `purgeExpired` reads the retention through the global `db` before opening any transaction. Inside the per-course transaction, every read uses `trx`.

## Deviations from Plan

- The verify commands `cd` into the main repo. I ran equivalent scripts (under `/tmp`) from the worktree, because worktree isolation rejects compound commands and the main checkout must not be touched. The CLI smoke also sets `CONTENT_STORAGE_PATH` to a temp dir so no real blob can be unlinked.
- `docs/DEPLOYMENT_TROUBLESHOOTING.md` already failed `prettier --check` before this plan (tables, emphasis). I left it unformatted to keep the diff to the new section.

- The plan deletes `course_modules` roots only and lets the cascade remove sub-sections. The service instead deletes every section id of the checked subtree, which it already holds for the live-descendant check. The result is the same: a sub-section the cascade already removed is a no-op delete.
