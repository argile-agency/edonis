<decisions_applied>
- **Selection model:** `selected: Set<string>` of row keys (`'s-12'`, `'c-34'`, from `rowKey`), held in the page next to `expanded`. Selection is data-based, not view-based: "Tout sélectionner" also selects rows inside collapsed sections. After every commit of `sections` / `contents`, keys of rows that no longer exist are pruned (`pruneSelection`). The selection is kept after an action (the teacher can chain "Publier" then "Décaler les dates…"), except for deleted rows.
- **Tree order (identical to 05-09):** a batch is processed in `buildRows(sections, contents, <all section ids>)` order. `selectedItems` returns that order; the optimistic move mirror applies the moves in it, one by one, each appended at the end of the destination, so the local result equals the DB (05-09 functional test "move contents": S2 = c1, c3).
- **Normalisation (identical to 05-09):** for move, duplicate and delete, an item whose ancestor section is selected travels with that ancestor (`topLevelItems`). Publish and availability apply to every selected item, with no cascade.
- **Controls (roadmap criterion 7, ≤ 3 interactions):**
  - `SelectionControls`, always rendered above the plan list:
    - a master `Checkbox` labelled "Tout sélectionner" (`checked` = all, `'indeterminate'` = some, unchecked = none; a click selects all, or clears when everything is selected)
    - a "Sélection rapide" `DropdownMenu` with "Tout sélectionner", "Tout désélectionner", "Éléments publiés", "Éléments non publiés", then one item per content type ("Pages", "Vidéos", "Fichiers", "Liens", "Devoirs", "Quiz")
    - the count in `<p id="builder-selection-count" aria-live="polite" aria-atomic="true">`: "Aucun élément sélectionné", "1 élément sélectionné" or "N éléments sélectionnés". It must NOT have `role="status"`: the 05-03 save indicator is the page's only `role="status"`, and the browser tests of 05-06 / 05-07 locate it with `getByRole('status')`.
  - `BulkActionBar`, rendered only when the selection is not empty: `<div role="group" aria-label="Actions sur la sélection">` with direct buttons "Publier", "Dépublier", "Disponibilité…", "Décaler les dates…", "Déplacer vers…", "Dupliquer", "Supprimer…" and "Désélectionner". Not `role="toolbar"`: a toolbar promises arrow-key navigation; plain Tab order is enough here. Publish and unpublish are direct buttons, not menu items, so "Tout sélectionner" → "Publier" is 2 interactions.
  - All buttons stay usable while a save is pending (the queue serialises).
- **Dialogs (shadcn, controlled, siblings of the bar; same focus rules as 05-05):**
  - "Disponibilité…": `Dialog` "Disponibilité des éléments sélectionnés", two `<Input type="date">` "Disponible à partir du" / "Disponible jusqu'au" (empty = no date, sent as `null`), "Annuler" / "Appliquer". From after until → no request, and "La date de fin doit être postérieure à la date de début." linked by `aria-describedby`.
  - "Décaler les dates…": `Dialog` "Décaler les dates". A `<fieldset>` with `<legend>` "Mode de décalage" and two native radio inputs with labels: "D'un nombre de jours" (number input "Nombre de jours (négatif pour avancer)", integer, not 0) and "D'une ancienne date de début à une nouvelle" (two date inputs "Ancienne date de début" and "Nouvelle date de début", both required). Help text: "Toutes les dates des éléments sélectionnés (disponibilité et échéance) bougent du même nombre de jours : les écarts sont conservés et les dates vides restent vides." Invalid input → no request and an inline message linked by `aria-describedby`. Sends `{ days }` or `{ from, to }`.
  - "Déplacer vers…": `Dialog` "Déplacer N éléments", description "Choisissez la destination. Les éléments seront placés à la fin, dans l'ordre du plan.", body `MoveTargetList` with `bulkMoveTargets(...)`.
  - "Supprimer…": `AlertDialog` "Supprimer N éléments", description "Supprimer les éléments sélectionnés ? Une section supprimée emporte son contenu, qui est sélectionné lui aussi. La progression des apprenants sur les contenus supprimés sera aussi supprimée. Cette action est irréversible.", "Annuler" / "Supprimer" (destructive). When `bulkDeleteBlockers(...)` is not empty, the "Supprimer…" button gets `aria-disabled="true"`, does nothing, and shows the visible reason "Sélectionnez aussi tout le contenu des sections à supprimer." linked by `aria-describedby` (D-05 pattern: discoverable, not Radix `disabled`).
  - "Dupliquer": no dialog (not destructive).
- **Bulk SaveOps (one per action, through `useSaveQueue`; built in the page like 05-06's ops):**
  - The items (kind and id) are fixed at enqueue time from the selection (tree order). Tokens are read from `sectionsRef` / `contentsRef` inside `run`, as in 05-06.
  - `apply` snapshots `{ sections, contents }`, then the optimistic change: publish / unpublish / availability → `applyBulkPatch`; move → `applyBulkMove`; delete → remove `bulkDeletedIds` through 05-06's id-list removal helper, and prune the selection; date shift and duplicate → no optimistic change (new dates and new ids come from the server).
  - `run`: `sendJson('POST', `/courses/${course.id}/builder/bulk/${action}`, body)`, then `mergeBulkResult(current, result)`, written through `commitSections` / `commitContents` (05-06's synchronous ref writes, so the next queued op reads the fresh tokens).
  - `rollback`: restore the snapshot. A 409 (stale item or `E_NOT_EMPTY`) shows its message through the indicator with "Recharger" (05-03 behaviour for `conflict`); a 422 shows its message.
  - Focus after a bulk delete: the master checkbox (the selected rows are gone). After a dialog closes: Radix returns focus to the bar button.
- **Merge rule (`mergeBulkResult`), binding:** remove the rows in `deleted`. For each id in `affected`, take the server row, but keep the local `title` and `description` when the row already exists locally (a rename queued after the bulk op may already be applied optimistically). Add the server rows in `affected` that do not exist locally (duplicates). Leave every other local row untouched.
- **Keyboard and drag (BUILD-16, 05-07 coexistence):** the checkbox is first in the row, then the handle. Space on the checkbox toggles it and starts no drag; Space on the handle starts a drag and does not change the selection; there is no multi-drag.
- **Not in this plan:** bulk group restriction, deploy to N courses, templates, upstream links (BUILD-V2-05..08); undo (BUILD-V2-01).
