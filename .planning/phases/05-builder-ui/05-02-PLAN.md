<contract>
<!-- The contract other plans (05-05, 05-06, 05-07) build against. Names and signatures are binding. -->
Types (exported):
- `ContentType = 'page' | 'file' | 'video' | 'link' | 'assignment' | 'quiz'`
- `BuilderSection { id: number; parentId: number | null; title: string; description: string | null; order: number; isPublished: boolean; availableFrom: string | null; availableUntil: string | null; updatedAt: string | null }`
- `BuilderContent { id: number; moduleId: number; contentType: ContentType; title: string; description: string | null; order: number; isPublished: boolean; availableFrom: string | null; availableUntil: string | null; updatedAt: string | null }`
- `BuilderRow = { kind: 'section'; key: string /* 's-<id>' */; id: number; depth: number; parentId: number | null; tooDeep: boolean; collapsed: boolean; section: BuilderSection } | { kind: 'content'; key: string /* 'c-<id>' */; id: number; depth: number; parentId: number /* moduleId */; content: BuilderContent }`
- `ItemRef = { kind: 'section' | 'content'; id: number }`
- `Placement = { parentId: number | null; position: number }`: for a content item, `parentId` is the destination section id (never null)
- `MoveTarget = { parentId: number | null; label: string; depth: number; disabledReason: string | null }`

Constants (exported): `MAX_SECTION_DEPTH = 1` (0-based: root = 0, sub-section = 1; D-02 = 2 levels); `DEPTH_MESSAGE = 'Profondeur maximale : 2 niveaux.'` (same text as the server); `NOT_EMPTY_MESSAGE = "Déplacez ou supprimez d'abord son contenu."`; `rowKey(ref: ItemRef): string`.

Functions (exported, pure, no DOM / React / dnd-kit imports, no imports at all):
- `sectionDepth(sections, id): number` and `sectionSubtreeHeight(sections, id): number`: client mirror of the server's `depthOf` / `subtreeHeight` (same conventions); they terminate on cyclic data
- `buildRows(sections, contents, expanded: ReadonlySet<number>): BuilderRow[]`: root sections (parent null, or parent missing from the list) by `(order, id)`. Under each expanded section come its contents by `(order, id)`, then its child sections, recursively. A collapsed section shows only its header row. Every section at any depth gets a row (legacy deep data stays visible, with `tooDeep = depth > MAX_SECTION_DEPTH`). The walk is cycle-safe through a visited Set.
- `sectionRowsForDrag(rows, activeKey): BuilderRow[]`: section rows only, without the descendants of the active section (used while a section is dragged)
- `projectContentDrop(rows, activeKey, overKey): Placement | null`: move the active row to the over row's index (`arrayMove` semantics). The parent is the nearest section row above the new index. The position is the number of that section's content rows between it and the slot, except when that section is collapsed, where it is its content count (end). Returns null when no section is above, or when the section is `tooDeep`.
- `projectSectionDrop(rows, activeKey, overKey, depthOffset: number, sections): (Placement & { depth: number }) | null`: `rows` = `sectionRowsForDrag` output. The projected depth is the active depth plus `depthOffset` (the caller passes `Math.round(deltaX / INDENT_PX)`, or ±1 from the keyboard), clamped to `[minDepth, maxDepth]`. `maxDepth = min(previousRow.depth + 1, MAX_SECTION_DEPTH - sectionSubtreeHeight(active))` (0 when there is no previous row); `minDepth = nextRow ? nextRow.depth : 0`. Returns null if `maxDepth < minDepth`, or if `maxDepth < 0`. The parent is the nearest row above with depth = projected − 1 (null for depth 0). The position is the count of rows above the slot whose `parentId` equals that parent.
- `moveTargets(sections, contents, item: ItemRef): MoveTarget[]`: destinations in tree order, labelled with their path ("Section 2 › Sous-section 2.1").
  - For a content item: every section. Its current section has `disabledReason` "Emplacement actuel", and a `tooDeep` section gets `DEPTH_MESSAGE`.
  - For a section: first `{ parentId: null, label: 'Racine du cours', depth: 0 }` (disabled "Emplacement actuel" when it is already a root), then every section. The section itself and its descendants get "Une section ne peut pas être placée dans elle-même ni dans une de ses sous-sections."; `sectionDepth(target) + 1 + sectionSubtreeHeight(item) > MAX_SECTION_DEPTH` gets `DEPTH_MESSAGE`; the current parent gets "Emplacement actuel".
- `siblingPlacement(sections, contents, item: ItemRef, direction: 'up' | 'down'): Placement | null`: the placement one step up or down among the item's siblings (contents of the same section, or sections with the same parent); null at the bounds
- `applyContentMove(contents, id, placement): BuilderContent[]` and `applySectionMove(sections, id, placement): BuilderSection[]`: return new arrays with `moduleId` / `parentId` and `order` updated exactly as the server does. Destination siblings ordered by `(order, id)` without the item, splice at `clamp(position, 0, n)`, dense `1..n+1`, and the source renumbered `1..m` when the parent changes.
- `canDeleteSection(sections, contents, id): boolean`: true only when there are no child sections and no contents
</contract>
