<contract>
<!-- Binding for 05-06. Every id is built from `idBase` = the row key ('s-12' / 'c-34'), never from a counter or useId. -->
`InlineTitle` (`inline-title.tsx`):
- Props: `{ idBase: string; title: string; kindLabel: 'la section' | 'le contenu'; editing: boolean; initialDraft?: string; errorMessage?: string | null; onStartEdit(): void; onCancel(): void; onSubmit(value: string): void; titleClassName?: string }`
- Read mode: a `<button type="button" id={`${idBase}-title`}>` whose visible text is the title, with `aria-label={`Renommer ${kindLabel} « ${title} »`}`. A click calls `onStartEdit`. The id is the focus target used by 05-06 after a save, a cancel or a delete.
- Edit mode: an `<input id={`${idBase}-title-input`}>` labelled "Titre" (a visually hidden `<label htmlFor>`), auto-focused with its text selected, and value = `initialDraft ?? title`.
  - Enter calls `onSubmit(trimmed)`; Escape calls `onCancel()`; blur calls `onSubmit(trimmed)` when the value changed, else `onCancel()`.
  - An empty trimmed value does not submit: it shows the local error "Le titre est obligatoire.".
  - `errorMessage` (for example the conflict text) is rendered in `<p id={`${idBase}-title-error`}>`, referenced by `aria-describedby` and `aria-invalid`.
  - After the switch back to read mode, focus returns to the title button (ref + effect).
- No pencil button inside: the row renders a pencil icon button that calls the same `onStartEdit`, `aria-label` "Renommer …".

`DetailsPanel` (`details-panel.tsx`):
- Props: `{ idBase: string; kind: 'section' | 'content'; values: { description: string | null; isPublished: boolean; availableFrom: string | null; availableUntil: string | null }; errorMessage?: string | null; onSave(patch: Partial<{ description: string | null; isPublished: boolean; availableFrom: string | null; availableUntil: string | null }>): void }`
- The root element is `<div id={`${idBase}-panel`}>`; the disclosure button (`aria-expanded`, `aria-controls`) lives in the row (05-06).
- Local field state is initialised from `values` on mount only. Prop changes do not overwrite what the teacher typed (D-09: input kept on conflict).
- Fields, each with `id={`${idBase}-<field>`}` and a `Label htmlFor`:
  - Description (`Textarea`): saves on blur when changed; empty sends `null`
  - "Publié" (`Switch`): saves on change
  - "Disponible à partir du" / "Disponible jusqu'au" (`<Input type="date">`): save on change or blur; empty sends `null`. Values are `yyyy-MM-dd`, derived from the ISO prop by taking the date part.
- When both dates are set and from > until: do not call `onSave`, and show "La date de fin doit être postérieure à la date de début." linked by `aria-describedby`.
- `errorMessage` is shown under the fields in an element referenced by `aria-describedby` on the panel's first field.

`ItemActionsMenu` (`item-actions-menu.tsx`):
- Props: `{ idBase: string; kind: 'section' | 'content'; title: string; canMoveUp: boolean; canMoveDown: boolean; onMoveUp(): void; onMoveDown(): void; moveTargets: MoveTarget[]; onMoveTo(parentId: number | null): void; canDelete: boolean; onDelete(): void; onCloseFocusTarget?: () => HTMLElement | null }`
- Trigger: a shadcn `Button` (variant ghost, size icon, at least 24×24 px) with `aria-label={`Actions pour « ${title} »`}` and the `MoreVertical` icon `aria-hidden`. The menu uses `DropdownMenu` / `DropdownMenuContent align="end"`.
- Items:
  - "Monter" / "Descendre": Radix `disabled` at the bounds is acceptable here, since it is a bound and not a rule to explain
  - "Déplacer vers…": opens a `Dialog` (title "Déplacer « {title} »", description "Choisissez la section de destination. L'élément sera placé à la fin.") listing `moveTargets` as `<button type="button">` items, indented by depth and labelled with `label`. A target with a `disabledReason` gets `aria-disabled="true"`, does nothing on click, and shows its reason as visible muted text linked by `aria-describedby` (id `${idBase}-target-<parentId ?? 'root'>-reason`). Choosing a target calls `onMoveTo(parentId)` and closes the dialog.
  - "Supprimer": when `canDelete` is false (non-empty section), the item has `aria-disabled="true"`, `onSelect={(e) => e.preventDefault()}`, a visible second line "Déplacez ou supprimez d'abord son contenu", and `aria-describedby` pointing to it. NOT Radix `disabled`, so it stays focusable and discoverable (D-05). Otherwise it opens an `AlertDialog`:
    - section copy: title "Supprimer la section", description "Supprimer la section « {title} » ? Cette action est irréversible."
    - content copy: title "Supprimer le contenu", description "Supprimer « {title} » ? La progression des apprenants sur ce contenu sera aussi supprimée. Cette action est irréversible."
    - buttons: "Annuler" (`AlertDialogCancel`) and "Supprimer" (`AlertDialogAction` with destructive classes as in `admin/categories/index.tsx`) calling `onDelete()`
- Focus: the Dialog, AlertDialog and DropdownMenuContent pass `onCloseAutoFocus={(e) => { const t = onCloseFocusTarget?.(); if (t) { e.preventDefault(); t.focus() } }}`, so focus never lands on a removed trigger (Pitfall 8 / Pattern 7).
- Open the Dialog and AlertDialog from the menu with controlled `open` state, set in `onSelect` after the menu closes (the usual Radix pattern of state outside the `DropdownMenuContent`). The global scroll-lock fix in `inertia/css/app.css` stays as is: no `modal={false}` and no body-style workarounds (Pitfall 10).
</contract>
