<objective>
Add true drag-and-drop on top of the page from 05-06, using classic `@dnd-kit/core` 6.3.1, `@dnd-kit/sortable` 10.0.0 and `@dnd-kit/utilities` 3.2.2, pinned exactly. The design is the flattened single-list pattern (RESEARCH Pattern 1) with two row kinds:
- contents drag in the full list (parent = the nearest section above)
- sections drag in a sections-only list with a horizontal depth projection, clamped to 2 levels (D-01, D-02 revised)

It also covers:
- collapsed and empty sections as targets, with auto-expand on hover (D-03)
- handle-only activation, including touch (D-08)
- the keyboard sensor with French announcements (D-07)
- SSR safety (Pitfall 1)

Every drop goes through the same `SaveOp` builder as the "Déplacer vers…" menu, so BUILD-10 behaviour (optimistic update, rollback, indicator) is identical.

- **Sensors:**
  - `PointerSensor` with `activationConstraint: { distance: 4 }` covers mouse, pen and touch through pointer events. The handle `<button>` has the `touch-none` class and a size of at least 24×24 px (`size-9`), and the listeners live only on the handle (`setActivatorNodeRef`), so touch elsewhere still scrolls (D-08, Pitfall 7).
  - `KeyboardSensor` with a `coordinateGetter` that branches on the active id prefix:
    - `c-` rows use `sortableKeyboardCoordinates`
    - `s-` rows use ArrowUp/ArrowDown through `sortableKeyboardCoordinates`, while ArrowLeft/ArrowRight return the current coordinates shifted by `∓ INDENT_PX` on x (`INDENT_PX = 24`, the row indentation)
  - This replaces the official example's longer `sortableTreeKeyboardCoordinates`. The depth offset for both pointer and keyboard is `Math.round(delta.x / INDENT_PX)`, read in `onDragMove`.
- **Content drag:** the `SortableContext` items are all visible row keys, and `projectContentDrop(rows, active, over)` gives the Placement on drop. A `null` projection cancels with an announcement and no save.
- **Section drag:**
  - In `onDragStart`, when the active key starts with `s-`, the rendered list switches to `sectionRowsForDrag(rows, activeKey)`: content rows and the active section's descendants are hidden for the duration of the drag, and the active row itself stays mounted.
  - `projectSectionDrop(sectionRows, active, over, depthOffset, sections)` gives the Placement. While dragging, the active placeholder row is indented at the projected depth, as visual feedback.
  - A `null` projection, meaning a depth overflow or a slot that orphans the next row, cancels with an announcement.
- **Keyboard reflow risk** (RESEARCH Pattern 1): hiding content rows above a dragged section can make the first ArrowDown skip rows. Task 3 has a test for it. If it fails and cannot be fixed by measuring (`MeasuringStrategy.Always`), apply the documented fallback: keep content rows mounted during section drags, and clamp section positions to after the destination parent's content rows in `onDragEnd`. Record which variant shipped.
- **Collapsed or empty targets (D-03):** collapsed section headers stay in the list. In `onDragOver`, when `over.id` is a collapsed `s-` row and a content item is dragged, start a 600 ms timer that adds the section to `expanded`. Clear the timer when `over` changes, or on end or cancel. `measuring={{ droppable: { strategy: MeasuringStrategy.Always } }}`.
- **Drop → save:** call the page's existing move-op builder from 05-06 (the same function the menu uses) with the projected Placement. Do not write a second save path.
- **French accessibility (Pitfall 9):**
  - `useSortable({ id: row.key, data: { kind: row.kind }, attributes: { roleDescription: 'élément déplaçable' } })`
  - handle `aria-label={`Déplacer « ${title} »`}`
  - `accessibility.screenReaderInstructions.draggable`: "Pour déplacer, appuyez sur Espace, utilisez les flèches haut et bas (gauche et droite pour changer le niveau d'une section), puis Espace pour déposer ou Échap pour annuler."
  - `accessibility.announcements`, built from a ref holding the latest projection: onDragStart "« X » saisi."; onDragOver "Sera déposé dans « S », position N." or "Emplacement impossible ici."; onDragEnd "« X » déposé dans « S », position N." or "Déplacement impossible : profondeur maximale de 2 niveaux."; onDragCancel "Déplacement annulé. « X » est revenu à sa place."
  - The root destination is named « Racine du cours ». Positions are announced 1-based.
- **No Dialog during a drag** (Pitfall 10). The global scroll-lock CSS stays untouched.
- **Coexistence with selection (revision 2026-10-31, D-11 / BUILD-16):** 05-06 reserved a selection checkbox slot in `builder-row.tsx`, rendered first and only when `onToggleSelect` is passed (05-10 passes it).
  - The checkbox stays outside the handle: the handle is its own `<button>` in the `handle` slot, and `listeners` / `attributes` from `useSortable` are spread on that button only, never on the `<li>` or on the checkbox. Activation is handle-only (already decided), so a pointer-down on the checkbox can never start a drag.
  - Keys: Space is both the checkbox toggle and the dnd-kit pick-up key (D-07). They never collide because the key acts on the focused element only: Space on a focused checkbox toggles the selection and starts no drag; Space on a focused handle starts a drag and leaves the selection unchanged. The checkbox is not rendered in this wave, so the browser test that proves both directions lives in 05-10 Task 4.
  - Dragging moves only the dragged row, even when other rows are selected: there is no multi-drag. Moving a selection is the bulk bar's "Déplacer vers…" (05-10).
