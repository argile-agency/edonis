<objective>
Build the autosave machinery (BUILD-10, within the guardrails of the "Claude's Discretion" section of CONTEXT.md). It is independent of the backend and of the tree rules, so it runs in wave 1.

The design follows RESEARCH Pattern 4 and Pitfall 4:
- **Transport:** `fetch` with JSON, not Inertia visits. Inertia 2.3.29 has no optimistic API, and its visits cancel each other.
- **One serial queue** with optimistic `apply`, `rollback` and retry.
- **Strict response checks:** `redirect: 'manual'`, and a JSON content type is required, so a Shield CSRF 302 or the HTML 404 page is never read as a success.
- **Indicator:** a visible `role="status"` indicator, with "Réessayer" outside the live region.
- **Navigation guard** while saves are pending.

The queue logic lives in a pure core (`inertia/lib/save_queue.ts`, no DOM, no React), unit-tested through Japa like `builder_tree.ts`. The DOM and React glue lives in `inertia/lib/builder_save_queue.ts`.

Output: the pure queue and its unit tests, the hook and fetch helper, and the status component. Plan 05-06 wires them into the page.
</objective>

`inertia/lib/save_queue.ts` (pure; no imports, no DOM, no React):
- `export type SaveErrorKind = 'conflict' | 'validation' | 'session' | 'forbidden' | 'error'`
- `export interface SaveError { kind: SaveErrorKind; status: number | null; message: string; body: unknown }`
- `export interface SaveOp { label: string; apply(): void; run(): Promise<void>; rollback(error: SaveError): void }`. `apply` makes the optimistic local change; `run` sends the request and reads tokens at run time, not at enqueue time; `rollback` undoes this op's own local change and receives the error, so a title op on `conflict` can keep the typed draft (D-09).
- `export type SaveStatus = 'idle' | 'saving' | 'saved' | 'error'`
- `export interface SaveQueueState { status: SaveStatus; error: SaveError | null; pending: number; failedCount: number }`
- `export function createSaveQueue(onChange: (state: SaveQueueState) => void): { enqueue(op: SaveOp): void; retry(): void; dismiss(): void; getState(): SaveQueueState }`
  - `enqueue`: calls `op.apply()` synchronously, then chains `op.run()` after the previous op settles. Status is `saving` while `pending > 0`, then `saved` when the queue drains without error.
  - When `run` rejects (any thrown value is normalised to a `SaveError` with `kind 'error'` unless it already is one), the remaining queued ops are not run. Rollbacks happen in reverse order: queued ops after the failed one receive `{ kind: 'error', message: 'Annulé après une erreur' }`, and the failed op receives the real error. The failed op and the cancelled ops are kept in their original order as the retry list. Status becomes `error`.
  - `retry()`: clears the error, then re-enqueues the retry list in original order (each `apply` again).
  - `dismiss()`: clears the error and drops the retry list (used after "Recharger").
  - An `enqueue` while in `error` is allowed; the new op runs normally and the retry list is kept.

`inertia/lib/builder_save_queue.ts` (DOM + React):
- `export function xsrfToken(): string`: same regex as `learn.tsx` lines 75-79. `learn.tsx` is NOT modified by this plan.
- `export async function sendJson<T>(method: 'POST' | 'PUT' | 'DELETE', url: string, body?: unknown): Promise<T>` throws a `SaveError`:
  - `res.type === 'opaqueredirect'` → `session` ("Session expirée ou jeton de sécurité invalide : rechargez la page.")
  - 401 → `session`; 403 → `forbidden` ("Action non autorisée.")
  - 409 → `conflict` (message from the body; `body` keeps `item`)
  - 422 → `validation` (message = `body.message ?? body.errors?.[0]?.message`)
  - a non-JSON content type or any other non-ok status → `error` ("Erreur du serveur (<status>).")
  - a `fetch` rejection → `error` ("Connexion perdue.")
  - Request options: `credentials: 'same-origin'`, `redirect: 'manual'`, headers `Content-Type: application/json`, `Accept: application/json`, `X-XSRF-TOKEN`
- `export function useSaveQueue(): SaveQueueState & { enqueue(op: SaveOp): void; retry(): void; dismiss(): void }`: one `createSaveQueue` per mount (`useRef`), state mirrored with `useState`. While `pending > 0`, it registers a `beforeunload` listener and an Inertia `router.on('before', ...)` guard that asks `window.confirm('Des modifications sont en cours d’enregistrement.
